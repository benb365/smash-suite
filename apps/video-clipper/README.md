# 羽毛球录像自动剪辑

选择拍摄类型和一份录像，自动识别对打回合、删除间歇，预览并保存带原声音的连续 MP4。界面使用浏览器，本机服务完成处理。

首版范围、处理行为和验收要求见[产品需求](requirements.md)。

## 运行测试包

完整解压仓库根目录 `dist/SmashSuite-macos-arm64.zip`，运行文件夹中的 `smash-suite`，保留同目录的配套资源。程序自动打开 `http://127.0.0.1:18780/`，请使用 Chrome 或 Edge。

测试包面向 macOS Apple 芯片，运行无需安装 Python 或 Node；首次识别联网下载模型，之后可以离线复用。当前 ZIP 为整理前已验证的版本，本轮源码更新没有重新打包。

## 使用

1. 选择比赛高视角、场边低视角或个人斜侧方，导入录像；邻场干扰明显时可圈选主球场。
2. 开始自动剪辑，等待识别与成片生成。
3. 播放预览，点击“保存 MP4”，通过系统窗口选择目录和文件名。

首版支持固定机位单打、横屏 H.264 MP4，验证目标为约 30 分钟、最高 1080p。每段默认前后各补 0.5 秒，三档质量均保留原尺寸和原声音。识别可能漏掉回合或多留间歇，需检查成片；尚无时间轴编辑、手动修正、历史任务或账号。

页面断连允许 60 秒恢复，超时或退出程序后清理临时录像与成片；已保存文件和模型缓存保留。详细清理规则及参数见[使用说明](usage.txt)，依赖来源见[第三方声明](THIRD_PARTY.txt)。

## 实现边界

程序只监听 `127.0.0.1`，同时提供静态网页、任务接口和进度连接。发行包包含 Python、FFmpeg、网页及必要算法实现，运行不依赖本仓库、实验目录或开发服务器。浏览器加载 HTML 和 Lynx for Web，由 `<lynx-view>` 加载编译后的 ReactLynx 操作面板；视频预览、文件选择和流式保存由网页宿主调用浏览器能力完成。

每个标签页持有随机临时凭证，只能访问自己的任务；进度连接持续续租，断连超时后取消任务并删除该会话的源录像、中间数据和临时成片。人物检测库配置和字体缓存也写入会话目录并随之清理。模型使用[模型模块](../../modules/models/README.md#环境与文件)规定的固定来源和 SHA256 校验，下载后放入应用独立持久缓存。用户通过系统窗口保存的成片不属于临时目录。Android 采集尚未接入本产品。

识别在独立工作进程中执行，应用将请求转换为场景、主球场区域、权重路径和工作目录参数，直接调用[回合模块](../../modules/rally/README.md)。高视角使用流式方案，场边和个人视角使用允许后续上下文的文件分析。原始区间另经每段前后各补 0.5 秒、裁界和合并，再交给媒体模块生成保留原音画相对偏移的连续 MP4；导出不修改原始识别区间。

工作进程显式报告识别、成片阶段的开始；服务用同一单调时钟统计准备、识别和生成成片耗时，三项之和等于启动任务至成片就绪的总耗时。统计随会话状态通过 HTTP/WebSocket 返回，刷新可恢复；新导入或新任务清空旧统计，不以进度百分比估算耗时。交付要求见[产品需求](requirements.md)。

## 开发

按[项目首页](../../README.md#开发工作流)安装共同环境后，在仓库根目录执行：

```sh
pnpm run dev:frontend
pnpm run dev:backend
```

服务和网页使用同一个 `http://127.0.0.1:18780/`。前端命令只构建静态文件；修改界面后重新构建并刷新页面，修改后端后重启服务。可用 `pnpm run dev:backend --no-browser --port 0` 选择空闲端口。

`frontend/` 是 ReactLynx 网页，`backend/app/` 管理接口、标签页会话和工作进程，`packaging/` 提供打包入口。识别调用[回合模块](../../modules/rally/README.md)，模型和音视频处理来自基础模块。

```sh
.venv/bin/python -m pytest apps/video-clipper/backend/tests
pnpm run typecheck:frontend
pnpm run build:product
```

打包仅支持在 macOS Apple 芯片上执行，输出到根目录 `dist/`。源码已接入新版 C/D；入口检查与完整产品验证分别记录。已安装产品的模型与工作目录仍位于自己的用户数据目录。
