# 查看器数据格式（schema_version: 1）

只提供保存的实际区间，不传 HTML、逐帧图像或模型对象。JSON 属于本次实验数据，放在相应模型的 `.runtime/` 下；播放器和服务代码只维护在 skill 内。

## 最小完整例子

```json
{
  "schema_version": 1,
  "title": "原方案与新方案对比",
  "note": "同一批视频和人工标注；参数不因展示而改变。",
  "primary_track": "current",
  "summary": [
    {"label": "对打时间保留", "value": "96.96% → 92.55%", "note": "已保存的评估结果"}
  ],
  "tracks": [
    {"id": "truth", "label": "人工回合", "role": "truth"},
    {"id": "current", "label": "新方案", "role": "prediction"},
    {"id": "previous", "label": "原方案", "role": "prediction"},
    {"id": "excluded", "label": "已确认还球", "role": "excluded"}
  ],
  "clips": [
    {
      "id": "A1-01",
      "title": "第1段（A1-01）",
      "video": "/absolute/path/to/clip.mp4",
      "duration_ms": 168000,
      "media_offset_ms": 91,
      "note": "时间从本段首帧算起。",
      "intervals": {
        "truth": [
          {"id": "1", "label": "第1回合", "start_ms": 4040, "end_ms": 9280, "review_status": "verified"}
        ],
        "current": [{"id": "1", "start_ms": 4120, "end_ms": 15320}],
        "previous": [{"id": "1", "start_ms": 3640, "end_ms": 9600}],
        "excluded": []
      },
      "issues": [
        {"label": "第1回合结束后多留", "start_ms": 7280, "end_ms": 17320}
      ]
    }
  ]
}
```

上例的数字只是形状示例，不是完整片段的标注或本次评估证据。使用时填写真实视频及对应完整数据。

## 字段与时间

| 字段 | 规则 |
| --- | --- |
| `schema_version`、`title` | 必填；版本当前为整数1，标题用人能理解的名称 |
| `tracks` | 全部视频共用的行定义；`id`为唯一非空字符串，`label`为显示名称，`role`为`truth`/`prediction`/`excluded` |
| `primary_track` | 可选，必须指向算法行；默认第一种算法，只决定模拟剪辑用哪种方案，不改变各行颜色或输出 |
| `summary` | 可选卡片列表；每项`label`、`value`为字符串，`note`可选。直接填写保存的正式评估数字，不让页面另算成功率 |
| `clips` | 至少一段；每段`id`唯一。`title`、`note`、`summary`可选 |
| `video` | 必填，本机可直接播放的MP4原视频；绝对路径，或相对于本JSON文件所在目录的路径。服务只暴露这里列明的视频，不复制或重编码 |
| `duration_ms` | 必填，片段时间轴的真实总时长，不含首帧播放偏移；不是根据文件名猜的秒数 |
| `media_offset_ms` | 必填，非负有限毫秒数。原生帧数据已减去首帧PTS时，填原视频首帧实际PTS（毫秒）；已经从零开始的预览填0。须来自媒体记录或实际首帧时间 |
| `intervals` | 必须包含每一个已声明的行ID；没有区间时填`[]`，不要用缺失字段猜测。没有人工标注时，直接不声明`truth`行 |
| `issues` | 可选，一键复看的窗口；每项有`label`、`start_ms`、`end_ms`，可以包含前后上下文 |

所有区间与问题窗口使用同一时间轴，必须满足 `0 <= start_ms < end_ms <= duration_ms`。不接受NaN、无穷、字符串时间、重复ID或越界区间；不自动裁短修正。

每行内区间`id`必须是唯一字符串（原评估的整数`rally_id`转成字符串即可），行与行之间不要求共用ID。按时间自动排序，不改坐标；`label`可选，建议人工回合填“第N回合”。

`truth`区间要求保留`review_status: "verified"`；`excluded`区间要求`review_status: "human_confirmed"`。草稿和算法猜测不能通过改字段伪装成人工确认。只查看待定材料时可以不提供人工行，把待定结果作为明确命名的算法行展示。

最多一行人工回合、一行已确认排除事件；算法行可有多种，按声明顺序用蓝、灰、紫、青等颜色。`excluded`行没有区间时自动隐藏。各行仍必须有明确名称，颜色不替代名称。

## 表格与正式成绩的区别

脚本根据同一份输入，为每个已确认回合列出每种算法所有重叠输出，不强行一一配对：

- 少留对打 = 该人工回合时长 − 与算法输出并集重叠的时间。
- 多留间歇 = 与该回合有关的输出并集，扣掉全部人工回合和已确认排除事件覆盖的时间。多回合共用同一输出时，这个值会在相关行重复显示，不能相加。
- 没覆盖已给人工回合的输出另列，**不自动称为误报**。人工可能只标了一部分视频。仅当整个输出落在同一个已确认排除事件内时标为“已确认排除事件内”。

正式漏检、误报、起止达标、3秒/5秒分组等仍取既有评估报告，作为`summary`原样显示。输入格式不要求复制匹配结果、逐回合审计字段或前端计算缓存。
