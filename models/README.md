# 模型目录

各模型的实现、权重、参数配置及运行中间数据放在对应子目录中。
本仓库使用的 TrackNet 实现和权重位于 `SoloShuttlePose/`；模型运行产物放在各自的
`.runtime/` 中。权重、上游模型文件及运行产物排除 Git 管理；本说明及
`SoloShuttlePose/configs/`中的少量实验参数纳入Git。
当前任务与进度以[路线图](../docs/plan/roadmap.md)为准。

## 名词解释

### 找球模型与观测

| 名词 | 在本仓库中的含义 |
| --- | --- |
| **TrackNet** | 从视频画面中定位羽毛球的模型。当前实现每次读取连续三帧，给出各帧的球位置和置信度；回合起止由后续分割规则判断。 |
| **权重（weights）** | 模型训练得到的参数文件。使用同一模型和权重，可以比较不同回合分割规则的效果。 |
| **热力图（heatmap）** | 模型对画面不同位置给出的响应图，用于寻找球的位置。当前实现从热力图中提取球坐标。 |
| **置信度（confidence）** | 当前实现取热力图的最大响应值，用于筛选观测。数值高不保证找对了球，也不能直接解释为“找对球的概率”。 |
| **候选球点** | 同一帧模型可能在几处响应。实验模式可记录最多32个局部最高点及各自分数，供前后帧检查；候选不等于已确认真球。 |
| **观测点 / 追球轨迹** | 按帧记录的球坐标、置信度及时间。模型可能漏掉球，也可能误追球员或背景，因此轨迹还需要后续处理。 |
| **有效运动观测（motion）** | 根据置信度、画面范围和观测点间的移动速度等条件筛选出的运动信号。它是算法判断依据，不等于已经确认发生了正式回合。 |

### 视频时间

| 名词 | 在本仓库中的含义 |
| --- | --- |
| **PTS（Presentation Timestamp，展示时间戳）** | 一帧在视频时间轴上应当显示的时间。PTS属于视频，不是TrackNet生成的。当前读取器使用实际解码帧的PTS，并以首帧为零点记录时间。 |
| **time_base（时间单位）** | PTS整数对应的时间刻度。例如时间单位为1/90000秒、PTS为90000，对应时间就是1秒。 |
| **原生PTS / 原始帧时间** | 沿用原视频的实际帧时间及间隔，避免仅按“帧号÷平均帧率”估算。报告中的“TrackNet原生PTS观测”，准确含义是“附带原视频帧时间戳的TrackNet追球结果”。 |
| **FPS / CFR / VFR** | FPS是每秒帧数；CFR表示帧间隔固定，VFR表示帧间隔可变。可变帧率视频尤其需要按实际PTS计时。 |
| **EOF（文件末尾）** | 视频已读完。当前模型每次处理三帧，文件末尾可能剩一至两帧尚未产生模型观测；“完整读入视频”和“每帧都有模型结果”需要分开记录。 |

### 回合分割与候选名称

下列名称是本仓库的实验编号，都复用同一个TrackNet找球模型，区别是如何把运动观测组织成回合。
`v1`表示该实验方案的第一版，不是TrackNet模型版本；`gap`表示允许的观测间隔，单位为毫秒。

| 名称 | 做法 |
| --- | --- |
| **流式（streaming）** | 随视频帧到达逐步判断，只使用当前及历史信息。回合结束确认后，可以回填此前的开始时间。 |
| **离线（offline）** | 允许在读取完整段视频或轨迹后，结合前后文判断回合。需要区分离线处理策略和文件读取速度。 |
| **streaming-flight-v1** | 现有流式候选：要求连续的运动观测建立候选；超过1600毫秒没有有效运动观测后，确认结束，回合终点仍取最后运动观测的时间。 |
| **offline-motion-v1-gap1600** | 读取整段运动轨迹，相邻运动观测间隔不超过1600毫秒就归为一组；组内至少三次运动观测、首末跨度至少2200毫秒才输出，文件读完后也处理末组。 |
| **offline-motion-v1-gap2400** | 与上一方案相同，将允许的间隔放宽到2400毫秒。更容易连接断续轨迹，也更容易把间歇中的零散误追串成一个回合。 |
| **trajectory-top-v1 / trajectory-single-flight-v1** | 第一版轨迹试验的历史名称：前者加入顶部出画连接，后者另试验严格单向过滤。当时要求几乎完整的坐标和开始前的静止球，实际没有过滤任何片段；对应旧报告保留原结果。 |
| **trajectory-record-only** | 当前轨迹判断，只记录保留、单向飞行候选或无法判断的原因，输出原高球连接后的全部区间。 |
| **trajectory-single-flight** | 试删有连续飞行、随后停止且没有持续返回证据的短片段；不要求开始前看到静止球。关键缺失和无法解释的局部反向仍保留。 |
| **trajectory-uncertain-short-trial** | 在上一方法基础上，进一步试删没有持续返回证据的不确定短片段，用来检查能减少多少误报、会误删多少正常回合；不是“已识别出还球”。 |
| **持续返回 / 局部变向** | 持续返回要求实际位移支持反向，前后还各有足够时长和距离的飞行；局部变向也可能来自放球、拍停、小反弹或检测抖动。两者都不能直接当作真实击球次数。 |

上述流式候选也使用2200毫秒的最短飞行跨度参数。它们是候选算法的参数，
不决定人工标注是否排除短回合；正常短回合若被漏掉，仍按评估规则计为错误。
首末运动观测也不保证恰好是发球触球或落地时间。

文件入口中的 `--mode offline` 仅表示尽快读取文件，默认仍运行原来的流式分割器；
两种 `offline-motion` 策略由[候选比较入口](../backend/tests/rally_benchmark/compare_m1.py)执行。
新轨迹方案通过文件入口的 `--segmenter trajectory` 选择，默认只记录判断。`filter_single_flight`
开启单向候选过滤，`filter_uncertain_short`开启不确定短片段试删；两项通过`--config`传入。
当前试验短时长上限为`short_event_ms=5000`，不是产品定义或人工排除标准。
当前回击速度变化门槛为`turn_jump_px_s=1100`像素/秒，统一按1920像素画面宽度换算；
它是拟合与相邻坐标计算的速度变化下限，不能当作真实击球识别的保证。
做法、参数、实测范围及局限见[给球过滤参数复查](../docs/experiments/m1-a-return-threshold-20261016.md)
及[此前还球过滤对照](../docs/experiments/m1-a-return-filter-20261016.md)；
[第一版轨迹报告](../docs/experiments/m1-a-trajectory-20261016.md)保留历史结果。

### 多候选离线试验

[坐标规则试验](../docs/experiments/m1-cd-coordinate-20261017.md)复用同一个TrackNet，
检查候选点是否在连续几帧形成短轨迹，再连接成回合。一条短轨迹只是几次观测，不是一个羽毛球回合；
前后连接也不表示已知道缺失处的真实飞行路线。C1另抑制整段反复响应的位置，并偏向画面中央，
因此会读取未来信息，只属于离线试验，不是新的流式能力。
C1/D1的分别试验参数保存在`SoloShuttlePose/configs/m1-cd-candidate-20261017.json`，
不用于自动切换所有视频的默认算法。位置抑制、中央偏向、轨迹要求都可能裁掉真实对打，须对照逐回合损失。

### 评估与结果

| 名词 | 在本仓库中的含义 |
| --- | --- |
| **rally（回合）** | 按人工标注口径，从发球触球开始，到落地或其他明确结束事件为止的时间区间。 |
| **标注 / 真值（ground truth）** | 用来对照算法结果的人工回合区间。`verified`表示已确认；`needs_review`表示仍待复核，不能作为正式目标计分。 |
| **temporal IoU（时间交并比）** | 预测区间与人工区间的重叠时长，除以两者合起来覆盖的时长。衡量时间重合程度，不是整个算法的准确率。 |
| **rally-iou-v2 / rally-iou-v3** | 本仓库统一回合评估器的版本名。先建立正时长重叠关系，再选择总IoU最大的全局一对一配对，同时统计漏检、误报、误切和误合并。`v2`支持已确认事件排除并输出误报计数；当前`v3`增加起点提前、终点延后各最多1.5秒的单向容忍。旧版本结果保留原口径。 |
| **漏检 / 误报** | 漏检：人工目标回合没有任何正时长重叠的预测。误报：计分预测没有任何正时长重叠的人工目标回合。“有重叠”不保证保留了完整回合。 |
| **误切 / 误合并** | 误切：一个人工回合与多个预测重叠；误合并：一个预测与多个人工回合重叠。当前分别按多出的区间数量计数，不能只看一对一配对结果。 |
| **边界达标 / 超限误差** | 当前起点可提前0–1.5秒，终点可延后0–1.5秒；晚开始和早结束均不容忍。区间内误差为0，区间外按距允许区间的距离计误差；主要报告起点、终点、双边达标数量及占全部确认目标的比例。误差分布只统计对应边界不达标的已配对回合。人工代表值采用已确认的start左端、end右端。 |
| **排除事件 / 忽略区间** | 人工确认不纳入本轮目标和主对错计数的还球、接发失败等事件。仅当预测完整落在同一个已确认排除区间内，且不重叠任何已确认目标回合时，忽略该预测；跨出区间仍正常计分。 |
| **对打时间保留 / 非目标时间残留** | 按时间并集计算预测覆盖了多少目标时长、额外保留多少非目标时长，重叠预测不重复计时。非目标补集未单独确认时，残留指标仅作暂定诊断。 |
| **benchmark / baseline** | benchmark是约定的测试数据、标注和评估规则；baseline是固定算法、参数和环境下测出的参照结果。测出基线不等于已经达到产品验收要求。 |
| **留出检查 / 独立来源验收** | 留出检查指配置固定后检查预留片段。同一录像的不同切片仍然相关；独立来源验收还需隔离原录像及相关拍摄会话。 |
| **轨迹缓存 / 回放** | 保存找球结果后，复用这些观测比较分割规则。缓存回放耗时需要与真实视频解码、模型推理耗时分开报告。 |
| **处理倍率 / MPS** | 处理倍率为视频时长除以处理墙钟时间，1倍表示处理耗时与视频等长。MPS是本项目运行TrackNet时可选的Apple GPU加速后端。 |

例如人工回合为10–20秒、预测为12–21秒：重叠8秒，合起来覆盖11秒，
时间IoU约为72.7%；起点晚2秒，超限误差2秒；终点延后1秒，在允许范围内，超限误差0。
这个IoU不能当作整体准确率。

正式定义以[需求与评估口径](../docs/plan/rally-segmentation-requirement.md)为准；
对应实现为[追球与流式分割](../backend/app/vision/tracknet_rally.py)、
[视频时间读取](../backend/app/vision/video_input.py)和[统一评估器](../backend/app/vision/rally_eval.py)。
