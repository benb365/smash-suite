## 已确认的效果与快速验证口径

- 优先保持结果一致。真实回合时长大于 3 秒时，不新增漏失，也不减少原本保留的对打内容；真实时长不超过 3 秒的回合，若有新增损失，须逐例人工确认；不新增独立的非回合片段。
- 3 秒只用于验收分组，不是算法新增的删短规则。效果取舍未授权降低导出画质。
- 使用当前原片和现有结果查看器检查变化。旧媒体标注或缺失的缓存不能代替本轮效果通过证据。
- 每项先选与该方向对应的一组短片，与保存的基线比较：D 姿态用 D-short（原基线完整处理耗时 335.08 秒），C 共享处理用 C-short（原基线完整处理耗时 137.17 秒），公共处理用 A-short（原基线完整处理耗时 48.05 秒）。这是单次观察，不推断稳定波动或长片效果。
- 默认不重跑长片、全组或多轮全量；只有结果不清楚或出现异常时，才针对该项补对照。新增预处理、扫描、读盘和编码都计入总成本，不得移出计时来显示收益。

## 想法边界与跨模块分工

粗筛方向沿用[想法与灵感](../../plan/ideas.md)：先用便宜步骤筛选，再对疑似或不确定片段按原片完整分析；原片始终保留。粗筛没有找到球、运动较弱或结果不确定，都不是可靠负例；未计算不能记作无动作，不确定时应进入完整分析。降低码率不单独列为首要方向；码率、像素尺寸、灰度和调用次数分别评估。

用户提出的双打想法另行规划，不并入当前性能优化任务。回合评估继续遵循[回合评估规范](../../../modules/rally/evaluation.md)，产品行为与输出要求见[自动剪辑需求](../../../apps/video-clipper/requirements.md)。本专题维护跨模块方案、进展和阶段总结；专项实验报告与测量证据仍归所属应用、模块或数据集，执行流水归 `docs/ai/`。本入口不复制基线明细或另建评估规范。

## 单项讨论与迭代方式

每项开始前先讨论清楚：要降低哪项已测成本、假设和证据、参数范围与固定项、短片和效果检查、资源代价、后续组合对象，以及继续或停止的条件。连续试验在已确认范围内执行；扩大方向、改变效果门槛或更换模型时重新讨论。未知参数、轮数和停止阈值保持待确认，不提前假定。

```text
讨论并确认方向与范围 → 单项小样 → 单变量试验（先粗后细）
                    → 保留有依据的候选 → 组合验证 → 记录结论
```

基线与当前最好候选都保留比较。一次试验失败不否定整个方向；试验也不作无边界穷举。结论应由同一输入、标注和评估口径支持，当前原片及现有查看器用于检查实际效果。
