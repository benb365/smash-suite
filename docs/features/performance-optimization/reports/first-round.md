# 首轮性能优化结果

## 结论

首轮保留三项：OPT-01 姿态计时诊断、OPT-03 C 场景重叠帧预处理复用、OPT-04 两处额外图像复制简化。独立验收通过；任务分支状态为“已完成，待人工确认”，等待人工确认集成，尚未合入或推送。

独立验收确认冻结文件、功能和代码检查通过；C 的真实 MPS 窗口与不提供帧号的路径一致，最终 D 区间、导出和保存姿态信号与原版相同，230.193 秒确认点得到保留。完整验收结论见[执行验收记录](../../../../docs/ai/performance-first-round/verifier/output.md)。

## 四项分别检查了什么

### OPT-01：D 姿态入口计时诊断

原版只记录整个姿态模型包装调用，无法区分包装器输入准备、模型调用和结果转换。此项在保留原口径的同时增加内部细分，用于定位成本，不改变识别逻辑，也不以诊断本身作为提速。

| 姿态计时项 | 历史 D 原版细分（秒） | 本轮 D 计时诊断（秒） | 说明 |
| --- | ---: | ---: | --- |
| 包装器输入准备 | 未记录 | 0.4523 | BGR 转 RGB、转张量、浮点转换与除以 255 |
| 模型调用 | 未记录 | 159.3075 | 包含模型内部归一化、缩放、网络及原生运算 |
| NumPy 结果转换 | 未记录 | 0.0251 | 从模型结果取得 NumPy 数据 |
| 整个姿态包装调用 | 162.02 | 159.8127 | 父项，包含包装开销；不得与内部子项相加 |

本轮模型调用约占包装调用的 99.7%。它包含模型内部处理，不是纯网络内核时间，也不是纯 Python 执行时间。包装器外的姿态解码 7.5064 秒、整帧转换 6.4229 秒不属于该包装调用；外层输入准备加结果转换约 0.48 秒，不支持优先把外壳迁移到 C++/Rust。改写内部热点仍需原生算子与 Python 自身成本证据。

### OPT-02：D 同帧批处理

原版逐人调用姿态模型；本项把同一帧的至多两张人物裁剪图组成一次模型调用，期望减少调用开销。总裁剪图仍为 2432 张，调用从 2432 次降为 1255 次，其中 1177 次双图、78 次单图。

| 回合片段 | 原版结束时间（秒） | 批处理结束时间（秒） | 对照判断 |
| --- | ---: | ---: | --- |
| 第 7 段，起点 100.9 秒 | 108.0 | 108.4 | 延后 0.4 秒，未单独完成人工效果确认 |
| 第 12 段，起点 215.7 秒 | 233.0 | 229.0 | 提前 4.0 秒，确认误删 |

**用户确认：230.193 秒处“球还没落地，理论上应该是强置信回合中”。** 批处理原始结束于 229.0 秒，加原有 0.5 秒尾部缓冲仍漏掉该点。最终逐人调用版结束于 233.0 秒，加同一缓冲后覆盖该点。这里不补造完整人工起止标注，也不据此计算整片准确率。

两次原版的源码、依赖快照、配置、输入与权重一致，工作量和输出也一致。模型调用分别为 159.31 秒和 175.13 秒；D 最终逐人组合的模型调用为 138.44 秒，外层输入准备仅从 0.45 秒变为 0.34 秒。整段差额远大于复制准备成本，具体运行差异原因未定位，不归因于复制简化或批处理的独立收益。

真实裁剪探针显示，批处理可能改变裁剪补边尺寸及模型输出，部分关键点偏差较大；尚未证明这是误删的唯一原因。先改善原有回合判断后可能规避误删，是待验证假设。本轮暂缓批处理，不实施条件批处理；后续应分别测量回合逻辑改进与批处理，再组合验证，并重查该案例及全部输出。[边界与人工判断记录](../../../../apps/video-clipper/reports/performance-first-round/d-batch-changes.json)。

### OPT-03：C 场景共享帧预处理复用

C 场景的相邻窗口会重复使用部分视频帧，原路径对每张模型输入都重新做预处理。此项按同一视频帧号复用最多三份 CPU 张量，减少重复颜色转换、浮点转换与缩放；模型仍按原窗口顺序逐组推理。

| 指标（单位） | 无缓存路径 | 本轮缓存单项 | 变化（含单位） |
| --- | ---: | ---: | --- |
| 模型调用（次） | 3599 | 3599 | 不变 |
| 模型图像输入（张） | 10797 | 10797 | 不变 |
| 准备单帧张量（次） | 10797 | 5400 | 减少 5397 次，约 49.99% |
| 复用已准备帧（次） | 0 | 5397 | 新增复用 |
| 缓存张量观测上限（帧） | 0 | 3 | 固定上限 |

减少约一半的单帧预处理不等于完整处理速度提升一半。最多三份 CPU float32 张量本体为 5.0625 MiB，不代表进程额外内存上限。缓存仅在 C 路径提供已知帧号时启用，任务结束或异常时清空。四组真实窗口的输入张量、热图（逐像素预测分数）和候选严格等价；窗口顺序和片尾处理不变。

TrackNet 预处理子项为历史 C 原版 18.06 秒、本轮缓存单项 9.21598 秒、缓存组合 9.36170 秒。旧路径 10797 次预处理依据旧源码和本轮输入张数推算，并非历史实测计数。该子项嵌套于视频观测，不能与完整处理阶段重复相加。[原始逐次数据](../../../../apps/video-clipper/reports/performance-first-round/measurement-summary/summary.json)。

### OPT-04：移除两处额外图像复制

OpenCV 颜色转换已生成独立、连续的 RGB 数组，原实现随后又调用 `.copy()` 复制一份。此项只移除这份额外复制，保留必要的颜色转换、浮点转换、缩放及模型内部处理；这样能明确少一次复制，且真实输入和结果必须保持等价。

| 子项 | 单项输入与检查 | 完整处理参照 → 本轮（秒） | 结论 |
| --- | --- | --- | --- |
| OPT-04a TrackNet | A-short；真实帧输入所有权、连续性和张量 | 历史 A 48.05 秒 → A 复制简化 43.56 秒 | 张量严格相同；完整 A 流程通过 |
| OPT-04b 姿态 | D 的 8 个真实裁剪；输入与张量数值、单图输出 | 未单独测姿态额外图像复制完整流程；在 D 逐人保留项组合中核对 | 数值与单图输出严格相同；完整 D 组合等价 |

D 保留项组合包含逐人调用、姿态额外图像复制简化及 TrackNet 额外图像复制简化，不是批处理组合。其与本轮 D 原版的差额不能归因于姿态额外图像复制简化；保留依据是严格等价且少一次复制，不宣称稳定提速。
