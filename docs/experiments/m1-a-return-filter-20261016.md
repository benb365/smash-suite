# A组给球与短片段过滤对照（2026-10-16）

已重写轨迹判断，并比较保留与试删不确定短片段的结果。在已经看过的A1四段视频上，
当前试删配置去掉4个误报，18个已确认正常回合全部保留，原来的六处高球连接也未改变。
只删较明确的连续单向飞行，则去掉其中1个误报。

这些参数已经参照A1的错误位置调整，不能当作新录像上的验收结果。默认仍只记录判断，
两项过滤开关均关闭。没有修改视频、人工标注或评估排除清单，也没有重新运行追球模型。

## 判断改了什么

用户所说的“漏球”指模型中途追不到球、坐标缺失。给球常伴随短时长和漏追，
但正常短回合也可能如此：A1-04有一个3.60秒的正常回合，可信坐标约44%，最长缺失1.92秒。
因此不能直接按“短、缺失多”断言是给球。

- **区分局部触球变化与持续返回。** 仍检查变化前后各4个可信坐标，但拟合出的反向必须得到实际位移支持。
  再检查变化前后各至少320毫秒、各至少120像素的飞行距离；距离统一按1920像素画面宽度换算。
  最多查看变化两侧各640毫秒的已收到坐标，不使用固定击球区域。只有速度变化不再单独否决单向飞行。
- **缺失处保持未知。** 相邻可信坐标超过120毫秒，或位置跳动超出速度范围，就分开记录，
  不补造一条飞行轨迹。短暂缺失用实际经过的时间计算。顶部出画仍沿用原来的位置、方向与等待规则。
- **允许没有开始前的静止球。** 取消95%的统一可信坐标门槛。较明确的单向候选需在5秒以内，
  有一段连续飞行、没有未解释的中间断点和持续返回，且结束后320毫秒内有至少200毫秒的静止支持。
  静止范围为16像素；轨迹最后同一范围内的小幅变向不再当作回击或无法解释的突变。
- **单独试删不确定短片段。** 对缺失较多、停止不明或只有局部变向的短片段，默认保留并记录原因；
  试删版另外删除5秒以内、没有持续返回证据的这类片段。持续返回和已连接高球均优先保留。

“持续返回”仍是坐标提供的候选证据，不代表识别到真实球拍、具体运动员或完整往返次数。
这些时间和距离都是本轮参数，不是产品限制，也不决定人工是否排除某个事件。

## 当前配置的结果

分母始终为18个已确认目标回合。“对打保留”是算法留下的人工目标时长比例；
“非目标残留”是额外留下的非目标秒数，已按同一人工排除规则处理。

| 方法 | 漏掉回合 | 一个回合切成多段 | 误报 | 对打保留 | 非目标残留 | 起止两端均达标 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 原逐帧判断 | 1 | 1 | 4 | 88.38% | 20.80秒 | 4/18 |
| 高球连接，过滤关闭 | 0 | 0 | 4 | 96.96% | 21.88秒 | 5/18 |
| 只删连续单向短片段 | 0 | 0 | 3 | 96.96% | 19.36秒 | 5/18 |
| 再试删不确定短片段 | 0 | 0 | 0 | 96.96% | 7.96秒 | 5/18 |

均没有把多个目标回合合成一段。三个高球连接版本的起点达标9/18、终点达标10/18；
起点可提前、终点可延后各最多1.5秒，向内裁切无容忍。过滤没有解决原有边界偏紧的问题。

### 哪些片段被删了

| 短片内位置 | 当前判断依据 | 只删连续单向 | 再试删不确定短片段 |
| --- | --- | --- | --- |
| A1-01 11.36–15.32秒 | 送球处有局部变向，但此前位移约56像素，不足以支持一段来球；另有漏追，停止不明 | 保留 | 删除 |
| A1-01 84.16–87.32秒 | 可信坐标约29%，没有形成足够持续的飞行，无法确定性质 | 保留 | 删除 |
| A1-02 75.96–80.24秒 | 放球附近局部变向，轨迹分段缺失；80秒处原先的假反向已排除 | 保留 | 删除 |
| A1-03 3.64–6.16秒 | 连续单向飞行，末尾小幅抖动后停止；没有持续返回 | 删除 | 删除 |

四段均没有与已确认目标或人工排除事件重叠，因此减少了4个计分误报。
删除第二段只表示试删在此样本上有效，不能据低可信比例认定它一定是给球。

**A1-03 110–120秒的已确认给球仍保留。** 当前参数在其中找到了足够的前后位移，
把它列为持续返回候选，说明这种轨迹检查仍不能识别所有给球。
该预测原本完整落在人工排除区间内，评估会忽略；本次没有给它新增排除资格，
也没有把它计作过滤成功。误报为0不代表所有垃圾时间都消失了。

## 参数为什么这样选

首轮要求变化两侧各移动160像素，试删版误删了A1-03的70.72–74.72秒，损失4秒正常对打。
这段在71.96–73.00秒有1.04秒漏追；73.36秒附近有实际回击，但返回侧位移约134像素，
没有达到160像素要求。补看了[实际帧](../../models/SoloShuttlePose/.runtime/m1-return-filter-20261016/a103-short-rally-review.jpg)
和坐标后，对照120与160像素，当前候选采用120。它保住了该正常回合，同时也保留了上文的已确认给球。

| 返回距离要求，短片段上限5秒 | 漏掉正常回合 | 误报 | 对打保留秒数 |
| --- | ---: | ---: | ---: |
| 两侧各160像素，试删不确定短片段 | 1 | 0 | 190.20 |
| 两侧各120像素，试删不确定短片段 | 0 | 0 | 194.20 |

在120像素配置上，再比较短时长范围；以下每行仍优先保留持续返回和已连接高球。

| 试删范围 | 漏掉正常回合 | 误报 | 非目标残留 |
| --- | ---: | ---: | ---: |
| 不超过3秒 | 0 | 3 | 19.36秒 |
| 不超过4秒 | 0 | 1 | 12.24秒 |
| 不超过5秒 | 0 | 0 | 7.96秒 |
| 不超过6秒 | 0 | 0 | 7.96秒 |

5秒覆盖了本轮四个误报，6秒没有增加收益。不能据此保证新录像的5秒短回合都不会被误删。

## 复现与验证

实现复用[现有轨迹模块](../../backend/app/vision/trajectory_rally.py)和
[比较入口](../../backend/tests/rally_benchmark/compare_trajectory.py)。从仓库根目录运行，使用尚不存在的输出目录：

```sh
.venv/bin/python backend/tests/rally_benchmark/compare_trajectory.py \
  --return-travel-px 120 \
  --output models/SoloShuttlePose/.runtime/m1-return-filter-reproduce
```

该命令比较四种方法，保存3/4/5/6秒试删记录；将参数改为`--return-travel-px 160`可复现距离要求的对照。
这是原模型坐标回放，不是视频解码或模型推理速度测试。仍只在回合结束确认后整理此前已收到的轨迹，
不提前读后面的帧，也不在文件末尾补造坐标或回合。

实际模型入口仍用`--segmenter trajectory`，默认只记录判断。通过`--config`传入以下内容可开启本轮试删配置：

```json
{"return_travel_px":120,"short_event_ms":5000,"filter_single_flight":true,"filter_uncertain_short":true}
```

90项后端测试通过，覆盖自然升降、持续返回、实际坐标与拟合方向不一致、停止附近抖动、
开始漏追、内部缺失、空观测、两种过滤开关及高球保留。
原逐帧方案的每帧结果、所有未过滤区间、六处高球连接事件均逐项复现；
5秒派生试删与实际启用过滤的输出指标、保留时长一致。
