## 数据与候选：这些名称是什么意思

[试验清单](../../datasets/badminton-v1/manifests/m1-a-trial-20261016.json)固定四段视频、已确认标注、原帧数量、默认模型配置和代码/权重哈希；共684.040秒、17,101个输入帧、18个已确认目标回合。

三个候选共用**TrackNet**：一个从视频画面中寻找羽毛球位置的模型。找球之后，再用不同规则把运动观测组织成回合。
**PTS**是原视频每帧的展示时间戳；沿用实际帧时间，不只按帧号除以平均帧率估算。
“TrackNet原生PTS观测”指附带这些原始帧时间的追球结果，不是TrackNet自己生成了时间戳。

| 报告简称 / 实验编号 | 实际做法 |
| --- | --- |
| 流式方案 / `streaming-flight-v1` | 随视频逐帧判断，只使用当前与历史信息。连续三次运动观测建立候选，超过1.6秒没有有效运动后确认结束；回合终点取最后运动观测，首末跨度至少2.2秒。 |
| 离线1.6秒 / `offline-motion-v1-gap1600` | 读取整段已有运动观测，相邻观测间隔不超过1.6秒就归为一组；至少三次观测、首末跨度至少2.2秒才输出；文件读完后也处理末组。 |
| 离线2.4秒 / `offline-motion-v1-gap2400` | 同上一方案，只把允许断追的间隔放宽至2.4秒。更容易接上漏掉的追球点，也更容易串入间歇活动。 |

这些名称是本仓库的实验编号，不是三种找球模型；`v1`是方案版本，`gap1600/2400`是允许间隔的毫秒数。
2.2秒是算法参数，不是人工排除短回合的阈值；正常短回合仍在目标内。离线分组不补造球位置或推测落地，只取首末运动观测。
更多解释见[模型名词表](../../models/README.md#名词解释)。

## 评估口径：表格怎么看

**rally-iou-v3**是本仓库的评估规则版本。先按时间重叠建立预测与人工回合的关系，再选择总时间交并比最大的全局一对一配对。
时间交并比（IoU）是重叠时长除以合并覆盖时长，帮助配对，不等于整体准确率。

- **漏检**：目标回合没有任何正时长重叠的预测；有一点重叠不代表回合完整。
- **误报**：计分预测没有重叠任何目标回合；**误切 / 误合并**分别指一个目标被多个预测重叠、一个预测重叠多个目标，按多出的区间数计数。
- **对打保留**：预测覆盖的目标时长占全部目标时长的比例，按时间并集计算，不重复计时。
- **非目标残留**：保留的非目标秒数，不含已确认排除窗口；非目标补集未单独确认，仍只作暂定诊断。
- **起点达标**：预测起点落在人工起点前1.5秒至人工起点的闭区间内。**终点达标**：预测终点落在人工终点至其后1.5秒的闭区间内。
- **双边达标**：同一配对预测的两端都达标。三种达标率都以全部目标回合为分母，未匹配目标不算达标；边界指标仍需结合误报、误切、误合并判断。
- **超限误差**：距允许区间的最近距离。提前2秒开始超限0.5秒；晚0.04秒开始计0.04秒；晚1秒结束达标，早1秒结束计1秒。没有额外的帧级容忍。

人工代表值仍为已确认的start复核区间左端、end右端，不等于已知精确触球或落地瞬间。
容忍区间不扩张人工标注，也不改变时间覆盖、IoU、排除事件及回合计数；误差分布只汇总对应边界不达标的已配对回合。
平均误差不再作为主要结论。P50、P95表示误差排序后第50%、95%位置的值，max是最大值，均以秒表示。

- A1-03用户已确认的110–120秒还球：三种候选均有一段完整落在窗口内，主指标各忽略1个预测；原9/9/8个预测分别计分8/8/7个。跨出窗口的预测不会整体免责。

## 新口径复评入口

在仓库根目录复用已有模型运行文件，下面两条命令不运行模型、不改变预测；输出目录已存在时更换新目录，不覆盖历史记录。
新配置锁只固定本次重评使用的候选和评估器，建立于已看过原检查结果之后；原v2锁不能用于v3，也不能通过修改旧锁哈希跳过检查。

```sh
.venv/bin/python backend/tests/rally_benchmark/compare_m1.py \
  --manifest datasets/badminton-v1/manifests/m1-a-trial-20261016.json --stage tuning \
  --runs models/SoloShuttlePose/.runtime/m1-a-tuning-20261016 \
  --output models/SoloShuttlePose/.runtime/m1-a-comparison-20261016/tuning-boundary-v3

.venv/bin/python backend/tests/rally_benchmark/compare_m1.py \
  --manifest datasets/badminton-v1/manifests/m1-a-trial-20261016.json --stage check \
  --runs models/SoloShuttlePose/.runtime/m1-a-check-20261016 \
  --lock models/SoloShuttlePose/.runtime/m1-a-comparison-20261016/tuning-boundary-v3/candidate-lock.json \
  --output models/SoloShuttlePose/.runtime/m1-a-comparison-20261016/check-boundary-v3
```

重评会核对视频、人工标注、原推理配置与运行来源记录，再从同一轨迹生成同样的候选预测并评分。
本次逐项核对确认：预测、标注、配对、IoU、排除结果、漏检/误报/误切/误合并及时间覆盖与原v2记录一致；只有边界评估口径变化。

## 当前结论与剩余工作

目前已经用A组四段视频实际运行并比较了三种回合识别方法。每种方法使用的参数、识别出的每个回合和处理耗时都已保存，后续改进时可以用相同视频、相同评分规则比较效果。测试工具已经能完成这些工作，但还没有选定最终采用哪种方法。

当前效果仍有明显问题：在留作检查的两段视频、共10个回合中，三种方法都只有2个回合的开始和结束时间同时符合要求。把允许漏掉追球点的间隔从1.6秒放宽到2.4秒，虽然找回了一个漏掉的短回合，却也把更多走动、等待等画面当成了回合。因此，仅靠“有没有追到移动的球”和“多久没追到球”来判断，还不足以做好自动剪辑。

之后已按用户要求检查出错位置，发现高球后约2秒看不到球时，现有规则会丢掉回合开头或把回合切断；还球和误追又需要分别处理。具体画面、原因和建议见[出错位置检查](m1-a-error-review-20261016.md)。本报告的三种方法和分数保持原样。
后续首版修改已实现，新的18回合对照结果见[轨迹规则实现与检查](m1-a-trajectory-20261016.md)；A1四段已全部用于改进和查错。

后续改进需要围绕这些具体原因展开，原有工作安排如下，其中第1项已有上述检查记录：

1. 对照出错位置，分别查清为什么把球员或背景误认成球、为什么开始切晚或结束切早，以及为什么多保留了回合结束后的画面。
2. 根据这些具体问题提出改法，讨论确认后再修改算法，并检查错误是否减少、有没有引入新的错误。
3. 改进后再找没有用于修改算法的其他原录像检查效果，可考虑之前保留的A2。A1的四段视频已经看过结果，继续用它们改算法后，分数提高只能说明在这些已知视频上有改善，还需要检查换一段录像是否也有效。

C、D组已经人工确认回合时间，但还没有运行这轮算法比较；后续怎么使用仍待确定。目前不能据A组结果判断它们的识别效果。
