# D组：减少捡球和还球残留，保住已找回的正常对打

2026-10-18。本轮在人物动作主导的方案上收紧球点的使用条件，比较了9种组合。较好的候选让**多保留的非回合内容从122.56秒降到98.30秒，减少24.26秒**；超过3秒的27个回合仍没有整回合漏掉，但其中两个回合的尾部合计少保留0.99秒。第4段的一次还球仍未解决，不能认为D组已经处理好了。

视频及同步时间轴见[对照网页](http://127.0.0.1:54052/)。绿色是人工回合，蓝色是本次改进，灰色是调整前的人物加球点方案，紫色是只用人物动作的原对照，橙色是人工确认的排除事件。页面设有具体问题的播放入口。

## 改了什么，为什么这样改

之前球点的作用过宽：一小段时间里只要出现过球，就可能放行只有一人明显动作的片段。这样的片段可能是真实对打，也可能是捡球、给球；保留后又会与前一个回合连在一起。本轮保留原人物模型、动作门槛和前后余量，分别试验动作是否得到支持、整段是否保留，以及相邻片段是否连接。

本次候选采用三项限制：

1. 只有一人出现明显手臂动作时，至少要有两次动作观测与球点同时出现，不能仅凭这段时间里某处出现过球。
2. 这种单人片段中，至少有一次明显手臂运动发生在手腕抬高或向身体侧面伸出的状态。
3. 某次手臂动作没有对方活动支持、只靠球点支持时，该次动作也必须符合上述抬高或侧向伸出的条件。得到对方活动支持的动作继续沿用原规则。

这里的“动作观测”是已有每秒5次采样中的记录，**两次观测不等于击球两次**。球点来自TrackNet，按约0.2秒的小时间窗归并；任一所选球员附近出现足够运动球点就可提供支持，尚未归属到具体击球者，因此“同时出现”也不能证明发生了击球。手臂运动沿用已有肩、腕位置及原画面的局部移动检查；抬高或侧伸只是姿态和移动条件，不能直接证明正在挥拍。本轮没有增加模型，也没有设置固定击球区域。

## 哪些尝试没有采用

单独限制“后一个单人片段不能跨空隙接入前段”，仅减少0.10秒非回合内容，却少保留约0.66秒正常对打，并多出一处单独误报。原因是部分坏片段在添加前后余量时已与前段重叠，之后才禁止跨空隙连接已来不及；分开输出也不会自动删除坏片段。这个方案不采用。

另试验了“两人动作至少交替两次才保留”，例如甲、乙、甲。它能删除第4段那次还球，但也漏掉第1段第7、第2段第6、第3段第6三个超过3秒的正常回合，长回合对打保留降至89.93%，不采用。人物动作记录会缺失、也会同时出现；动作交替不能当作可靠的击球交替。

其余组合及每段的全部预测、评分保存在[结构化结果](d1-refined-person-20261018.json)。没有只展示最好的单个片段，也没有据算法输出移动人工边界。

## 当前判断与下一步

人物动作仍应主导D组判断，球点保留为辅助；收紧球点支持确实能减少一部分垃圾时间，同时保住两个容易被删掉的正常回合。只用人物动作的残留更少，但会漏掉两个超过3秒的回合，目前仍有保留对打与删除间歇的取舍。

接下来优先分析第4段49.756–57.456秒的还球与第3段两个回合尾部：它们仍能满足现有动作支持，单纯要求双方交替会伤及正常对打。第2段两个少留尾部也需结合视频判断后续改动能否补回，不能把0.99秒损失藏在总保留率里。

这四段来自同一原视频，已用于调试，结果不能代替新来源验证。A、C方案与正式入口未改。本轮复用保存的人物和球点数据，没有重新推理、训练或下载权重；因此没有新的模型速度结论。现有人物选择和活动支持仍使用完整片段或后续观测，本候选尚未证明符合实时处理要求。

核验已完成：原输出逐条复现，8种组合共32项片段结果重新评分，预测区间、标注及输入哈希、独立时长差集均通过；交替动作试验另有基线复现和失败记录。运行材料位于`models/SoloShuttlePose/.runtime/d1-person-motion-20261017/d1-refined-person-20261018/`，包括`refine.py`、`comparison.json`、`alternation_trial.py`、`alternation-comparison.json`、`audit.json`及查看器数据`review.json`。固定查看器的播放、时间联动与切换已实际检查；本轮未修改产品代码。
