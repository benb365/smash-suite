## 结果如何理解

“完全漏掉”表示一个人工回合没有任何预测覆盖；覆盖一点也可能算未漏掉，因此必须同时看对打时间保留和逐回合损失。
“误报”表示预测没有覆盖正常回合；“误切/误合并”分别表示一个回合切成多段、多个回合连在一起。
“非目标残留”是预测覆盖的目标回合之外时间，扣除人审排除事件；这部分尚未逐帧标成负例，继续只作诊断。

| 来源、方法 | 完全漏掉 | 误报 | 误切 / 误合并 | 对打时间保留 | 非目标残留 | 起点 / 终点 / 两端均达标 |
| --- | ---: | ---: | --- | ---: | ---: | --- |
| C1原轨迹规则，不删短片段 | 4 | 14 | 0 / 1 | 77.53% | 240.513秒 | 3 / 5 / 0，共18回合 |
| C1本轮折中参数 | 0 | 13 | 0 / 0 | 95.39% | 154.327秒 | 5 / 5 / 1，共18回合 |
| D1原轨迹规则，不删短片段 | 11 | 8 | 2 / 0 | 51.35% | 63.045秒 | 6 / 5 / 2，共32回合 |
| D1本轮保留优先参数 | 0 | 5 | 0 / 0 | 84.24% | 161.301秒 | 7 / 3 / 0，共32回合 |
| A1原已选方案，本轮复现 | 0 | 0 | 0 / 0 | 96.96% | 7.960秒 | 9 / 10 / 5，共18回合 |

边界沿用`rally-iou-v3`：起点可提前0–1.5秒，终点可延后0–1.5秒；向内切掉对打没有容忍。
D1两端均达标从2/32降为0/32，说明“找回更多对打”和“正确判断起止”仍是两件事。
A1的输出和已选过滤规则保持原样，未把C/D的新规则设成所有视频的默认方案。
此前A1的“不确定短片段试删”会误删C/D正常回合，本轮新参数没有继续套用该过滤。

## 实际改了什么

原模型每次输入三帧，仍只运行同一套TrackNet权重。现在可额外记录每帧最多32个候选球点，
每个分数来自对应位置；原来返回的单个球坐标完全保留，12片均与旧缓存逐字节相同。
候选是模型响应，不保证一定是真球。

新的实验方法检查候选点能否在连续几帧形成短轨迹，再把相隔不太久的飞行证据连接成回合：

1. 不只选择单帧分数最高的位置，保留少量可能的前后路径，检查速度和与前两点运动趋势的偏离。
2. 要求轨迹有实际位移，固定背景点不能仅凭高分延长回合。C1另压低整段反复出现位置的响应，并偏向画面中央。
3. 对连接后过于零散的片段检查支持观测的数量和时间比例；所有位置都来自实际观测，缺失处不补坐标。
4. 回合边界取支持观测的实际时间；不添加片头片尾补时来改善评分。

C1的中央偏向是明确的画面构图假设，不是自动识别出了主球场；主球场不居中时可能失效。
反复出现的位置也可能与真球经过处重合，因此这项抑制并非无损。
D1关闭这两项：实际球可能经过海报附近，按整段重复位置屏蔽会继续漏掉真球。

| 参数 | C1折中 | D1保留优先 |
| --- | --- | --- |
| 候选最低分 | 0.5 | 0.5 |
| 短轨迹最少点数 / 时间 / 位移 | 4点 / 160毫秒 / 80像素 | 3点 / 60毫秒 / 20像素 |
| 下一点相对运动趋势的最大偏离 | 48像素 | 24像素 |
| 允许两段证据之间的最长间隔 | 2400毫秒 | 3200毫秒 |
| 一组最少跨度 / 观测数量 | 1600毫秒 / 18点 | 600毫秒 / 18点 |
| 其他条件 | 支持时间比例至少45% | 支持时间累计至少1200毫秒 |

距离统一按1920像素画面宽度换算。支持时间是相邻支持观测间隔的累加，每段最多记100毫秒，
只是衡量证据是否零散，不是测得的真实飞行时间。

**这套新方法是离线试验。** C1的位置统计读取整段，短轨迹也会回头确认较早帧；文件末尾输出的时间仅作记录，
不能当成新的流式处理能力或实际延迟。流式方案和正式内部架构仍需后续选择。

## 比较过哪些取舍

本轮从既有参数比较继续，依次试了原单点坐标的局部运动一致性、多候选按分数/连续性选点、
反复位置抑制与中央偏向、多帧轨迹、较短三帧轨迹、组内证据密度。
单独提高分数、只缩短等待或继续试删短片段，都不能同时保住正常回合并删除间歇。
另试用旧方法的相邻边界补充新结果，收益较小且增加残留，没有维护这项规则。
全部实际尝试的文件、配置数量、校验值和结果索引在[结构化记录](m1-cd-coordinate-20261017.json)。
配置组合大量重复，不代表独立测试样本。

保留下列可复现取舍，避免把一个数字说成唯一最优；95%只用于选取表中折中例子，不是新增验收门槛。

| 参数取舍 | 对打保留 | 误报 | 非目标残留 | 两端均达标 |
| --- | ---: | ---: | ---: | --- |
| C1保留更多对打 | 98.38% | 20 | 251.953秒 | 1/18 |
| C1折中，本轮主要结果 | 95.39% | 13 | 154.327秒 | 1/18 |
| C1少留间歇 | 90.01% | 11 | 95.060秒 | 0/18 |
| D1保留更多对打，本轮主要结果 | 84.24% | 5 | 161.301秒 | 0/32 |
| D1少留间歇 | 73.60% | 8 | 65.122秒 | 1/32 |

这些例子均没有整回合漏掉、误切或误合并，但会裁掉部分正常回合。
交叉套用也不可靠：C1折中参数用于D1仍漏11回合、保留44.28%；
D1保留参数用于C1会误合并10次、残留480.358秒。C1参数用于A1也低于A1原方案。
因此暂存分来源实验参数，未实现自动判断视角或通用参数选择。

## 逐回合检查与剩余错误

已经核对C/D全部50个正常回合，新参数没有新增整回合漏检；相对原未过滤方案，
C1有7个、D1有3个回合保留更短。以下不是平均误差，完整明细见结构化记录的`truth_audit`。

| 回合 | 人工区间 | 原保留 / 新保留 | 说明 |
| --- | --- | --- | --- |
| C1-01回合2 | 28.318–43.794秒 | 15.476 / 11.674秒 | 少3.802秒，是C1最大的新增损失 |
| C1-02回合2 | 42.726–45.595秒 | 2.869 / 1.801秒 | 新方案只保留62.77%，不能视为完整找回 |
| C1-03回合1 | 43.226–45.494秒 | 2.268 / 1.634秒 | 正常短回合仍被切去一部分 |
| D1-02回合4 | 42.367–47.800秒 | 0 / 2.300秒 | 找回了部分，但只保留42.33% |
| D1-03回合1 | 10.367–13.633秒 | 0 / 1.567秒 | 只保留47.96%，终点过早 |
| D1-04回合1 | 2.867–7.700秒 | 3.300 / 3.067秒 | 仍比原方案少0.233秒 |

另按真实帧号和PTS查看上述低保留回合、最大新增损失及两组最长误报的18个原帧。
C1的正常对打两端缺少通过轨迹检查的观测，原坐标也有指向邻场的情况；
C1-03的99.761–114.236秒误报仍包含等待阶段、邻场/背景响应，连续点不能说明主场正式开打。
D1-02的42.367–47.800秒有前景人员遮挡，部分模型点指向身体、海报或地面；
D1-03也存在对打结束前缺少支持轨迹。D1-01的33.900–44.100秒误报表明准备/停顿阶段同样能产生短轨迹。
抽样不能证明每帧都因同一原因出错，也没有据此重写人审标签。
[原帧与坐标索引](../../models/SoloShuttlePose/.runtime/m1-cd-coordinate-20261017/final-frame-index.json)
保留候选点、选点、原点、帧号、PTS和校验值；两张复核图与此前全部错误材料保留在相同模型缓存目录。

当前证据说明：还需要可靠区分主场与邻场、准备与正式对打，并补足被遮挡或漏追时的起止证据。
不能据本轮结果宣布“单靠轨迹已经无解”，也不能把困难回合直接排除或把这些条件提前写成已确认产品限制。

## 如何复现与核验

参数在[模型配置](../../models/SoloShuttlePose/configs/m1-cd-candidate-20261017.json)，
实现分别为[多候选轨迹检查](../../backend/app/vision/candidate_rally.py)和
[完整对照入口](../../backend/tests/rally_benchmark/compare_candidates.py)。默认产品入口未切换。

已有本地候选缓存时，使用新的输出目录：

```sh
models/SoloShuttlePose/.venv/bin/python backend/tests/rally_benchmark/compare_candidates.py \
  --manifest datasets/badminton-v1/manifests/m1-cd-coordinate-trial-20261017.json \
  --profiles models/SoloShuttlePose/configs/m1-cd-candidate-20261017.json \
  --runs models/SoloShuttlePose/.runtime/m1-cd-coordinate-20261017/inference \
  --output models/SoloShuttlePose/.runtime/m1-cd-coordinate-reproduce
```

重新运行视频和模型时，在该命令增加`--infer --device mps`，并把`--runs`与`--output`均改为尚不存在的目录。
这会复用现有文件读取和模型入口，再执行同样的对照；不会下载模型、改变视频时间或覆盖旧产物。
本轮已实际完成12片真实模型运行及上面的缓存对照；`--infer`组合启动参数本身未重复执行第二轮。
