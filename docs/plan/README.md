# 计划文档维护手册

`docs/plan/roadmap.md` 是当前优先级、状态、证据、阻塞和下一项工作的唯一来源。

## 文件职责

- `roadmap.md`：有序执行计划和里程碑状态。
- `rally-segmentation-requirement.md`：输入输出要求、seed 数据、标注与统一指标。
- `video-clipping-product-task.md`：首个视频剪辑产品的会话分工、复用格式、实施顺序及交付要求；实时进度仍只写入 `roadmap.md`。
- `../architecture.md`：已接受的系统边界；只有完成 benchmark 和选型记录后，才写入正式内部架构。
- `../features.md`：稳定产品范围与非目标。
- `../../backup/docs/`：历史快照，不参与任务选择或当前设计判断。

## 选择工作

当用户没有指定任务时：

1. 从 roadmap 的 `Current Focus` 开始。
2. 优先处理最低编号优先级。
3. 同优先级按 `In Progress`、`Next`、`Todo` 排序。
4. 最高优先级若为 `Blocked`，只解决或记录该阻塞，不静默转向低优先级功能。
5. 完成条件或证据缺失时，先补齐计划，不直接实现。

## 更新状态

每个里程碑使用以下状态之一：

- `Todo`：尚未开始。
- `Next`：当前最高优先级的下一项。
- `In Progress`：已有正在进行的实现或验证。
- `Blocked`：存在明确阻塞，必须记录解除条件。
- `Done`：完成条件满足且证据可复查。

状态变化必须同时更新完成证据、剩余缺口和阻塞。代码存在、命令成功或旧实验产生过结果，都不自动等于里程碑完成。

## 证据要求

- benchmark 工作记录数据集清单版本、标注版本、运行命令、算法配置、逐回合结果和汇总指标。
- 候选路线使用统一输入输出契约，不得用各自不同的评估口径比较。
- 评估报告优先用日常语言说明做了什么、发现什么问题、下一步做什么；结论不堆砌实验代号或流程名词。确有必要的术语首次出现时就地解释，可附名词表链接，不能只靠读者查代码或另查文档。
- 起止边界按requirement的单向1.5秒容忍规则报告达标数量/比例及未达标案例，平均误差不作主要结论；改口径后注明评估版本并保留旧评估证据。
- 架构选型引用 benchmark 与选型记录；证据不足时保持未选型。
- 旧代码、旧 trace、旧参数和 `backup/docs/` 只能作为明确标注的“历史假设”，不能作为当前完成证据。

## 同步规则

- 当前优先级、进度、证据或阻塞变化：更新 roadmap。
- 数据、标注或指标定义变化：更新 requirement。
- 产品范围变化：更新 `docs/features.md`。
- 公共契约或被接受的内部架构变化：更新 `docs/architecture.md`。
- 文档所有权或 Agent 阅读路径变化：更新 `docs/README.md` 和必要的 `AGENTS.md`。

文档更新应与对应变更同批完成。归档文件保持历史原貌；若需解释，只在归档索引补充，不回写成当前事实。
