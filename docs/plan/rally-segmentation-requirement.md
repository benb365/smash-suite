# 流式回合分割需求与评估

## 目标

系统消费时间戳严格单调递增的视频帧，在确认一个羽毛球回合已经结束后，一次性输出该回合的完整时间区间。

核心结果是时间边界，不生成视频片段。算法必须在线工作：处理当前帧时只能使用当前及历史信息，但允许在结束确认后回填开始时间。

输入与输出字段以[系统边界](../architecture.md)为准。

## 功能要求

1. 逐帧接受 `TimestampedFrame(frame_id, timestamp_ms, image)`。
2. 对乱序、重复或回退的时间戳明确报错，不静默重排。
3. 每个已确认回合只输出一个 `RallyInterval`。
4. 输出满足 `start_ms <= end_ms <= emitted_at_ms`。
5. 未确认结束的候选回合不对外承诺结果。
6. 本地视频 replay 与真实帧生产者使用同一分割器契约。

## 回合边界定义

回合时间区间采用以下口径：

- `start_ms`：发球时球拍击中球的源时间戳，不包含发球准备。
- `end_ms`：球落地，或出现其他能明确确认回合结束的事件的源时间戳。
  触网后继续飞行、球员停步或运动减小本身不作为结束依据。
- 结束确认可以晚于结束事件；等待确认的时间体现在 `emitted_at_ms`，
  不延长回合本身的 `end_ms`。
- 看不清起止事件的片段标记为不确定，保留待人工审核记录，不猜测边界，
  不进入正式 verified 回合评测。
- 导出时的片头片尾补时独立于真实回合区间，不拿补时后的区间替代算法预测评分；预测边界本身按下文单向1.5秒容忍规则评估。

人工采用边界区间时，保留区间、原帧和审核决定。经人工确认的保守取值规则为
start取区间左端、end取区间右端；代表值不等于已知精确触球或落地瞬间，不能把区间宽度解释为0，
也不能将边界规则的确认扩展为未审核素材的内容确认。尚未审核的区间继续保留待审状态，
部分覆盖之外不作为无回合的负例。边界误差评估须明确使用保留区间或代表值的口径。

既有人工标注保留原时间戳和审核记录，继续用于历史诊断。用于新口径的
正式 benchmark 前，须逐段核对是否符合上述定义，并记录复核与标注版本；
原 `verified` 状态不代表已完成这次语义核对。

### 可排除的事件

还球不属于正式回合。接发失败等超短回合允许不纳入本轮目标回合及主成功率判定，
但须单独保存事件类别、时间范围、排除原因和审核状态，保留原素材及原标注记录。
不设未经确认的秒数阈值，不仅因难识别或持续时间短就自动排除正常对打。

评测对已确认排除的事件采用同一排除清单：不计目标回合数及成功率分母，
对应预测也不计成功、漏检、误报或边界误差。不能只删人工标签而将对应预测当作误报，
也不能因预测与排除区间有一点重叠就免除整个跨区间预测的错误。
2026-10-16 用户确认跨区间规则：仅当预测完整落入同一个已确认排除区间，且与任何
verified目标回合没有正时长重叠时，忽略整个预测；跨出排除区间的预测仍按原区间计分，
不裁短、不拆开、不因一点重叠而免责。待审事件不能触发排除，所有候选共用该规则。
结果保留排除事件、忽略预测及其对应事件、原预测总数和计分预测数。

“只有一次单向飞行、没有回击”可以作为还球或接发失败的待验证判断线索，
但必须先检查轨迹是否足够完整、可信。没追到返球不等于没有返球；
高球自然上升后下降，也不等于被对手回击。需要检查突变前后的连续飞行是否支持回击，
并与自然升降、反弹和误追区分；不要求预先配置固定击球位置，不能只数画面坐标的方向变化或按持续秒数删除。
短时间内仍可能发生正常来回，对这类已确认目标仍按原规则计分。
用户所说的“漏球”指模型中途追不到球、坐标缺失。给球可能同时表现为片段短、轨迹零碎，
这两项作为待验证线索，不能独立证明没有对打。判断需区分局部触球变化与持续返回的飞行，
缺失处不补造坐标，也不统一要求95%的可信坐标或开始前看到静止球。
用户已同意对无法确定的短片段同时比较保留与试删结果，逐段报告减少的误报和误删的正常回合；
已连接的高球与有持续返回证据的片段优先保留。时间、距离等试验参数不自动成为产品限制。
算法将片段判为还球或超短事件，不会自动使该片段成为评测中的人工排除事件；
是否能自动判断、误删多少正常回合，须另行测试，人工真值与成功率分母保持不变。

## 回合算法测试视频

测试范围为固定机位单打，视角分类包括官方高视角、非官方高视角、场边低视角、
个人录制常见的斜侧方视角。各类分别评估；当前纳入或暂缓的类别由[路线图](roadmap.md)维护，
暂缓类别不作为本轮达标条件。来源视频及其分类需要人工参与并确认。

先找到合适的来源视频，再从中截取连续片段作为测试输入。每个当前纳入类别累计有效测试时长
至少 10 分钟，不固定视频数量、单段时长，也不要求每段覆盖完整一局。
片段需保留对打和间歇，不能只拼接独立回合；同一来源的重复或重叠内容不重复计入时长。
记录来源、截取窗口、实际时长、原始帧率或时间戳、文件校验值和人工分类结论。

迭代与验收按来源和相关拍摄会话隔离；同一录像的不同片段不能分别用于调参和独立验收。
每类的时长目标针对该类整个测试素材池，不额外要求迭代集、验收集分别达到 10 分钟，
也不规定两者的固定视频数量配比。多场地录像允许人工指定主球场，候选使用相同信息。
实际分类、时长缺口及进度只维护在[路线图](roadmap.md)。

### 视频使用条件与待验证的限制

当前测试范围已经限定为固定机位单打。还需在试验过程中持续记录哪些录像条件会导致
算法无法可靠判断，再决定是否成为首版对使用者的要求；不能先按有利条件删除困难样本。

| 条件 | 当前处理方式 | 需要通过试验回答的问题 |
| --- | --- | --- |
| 固定机位、单打 | 已确认的当前测试范围；不据此宣称支持双打或移动拍摄 | 现有不同视角下是否都能达到所需效果 |
| 球场完整入画 | 待验证的使用限制，尚未确认为硬要求 | 两端底线、发球区或结束位置被裁掉时，是否影响回合判断；最终需要完整球场，还是只需关键区域可见 |
| 球的完整飞行轨迹入画 | 待验证的使用限制，尚未确认为硬要求 | 顶部短暂出画能否可靠连接；若能，允许怎样的出画情况；若不能，是否需要要求镜头上方留足空间 |
| 相邻球场同时活动 | 待验证；须区分用户所指主场与邻场，移动的白点本身不足以判断归属 | 是否需要主球场居中、减少邻场入画，或由用户提供主场信息；尚未确认为产品限制 |
| 球足够清楚、关键时刻不被长时间遮挡 | 待验证，尚未规定分辨率、帧率或遮挡时长门槛 | 轨迹缺失到什么程度会无法区分高球、回击、还球和落地；误追人物/场边能否通过轨迹检查排除 |

每项记录具体样片和出错位置、看不到的内容、已尝试的处理及结果、还会误删或多留哪些画面。
处理尚未验证时，明确标为待验证；只有确定能力范围并确认取舍后，才形成产品限制。
记录实际试验结果和待办的入口为[路线图](roadmap.md)，首版使用条件最终随M2产品规格确认。

## Seed benchmark

第一份 benchmark 复用现有资产：

- 样片：`datasets/badminton-v1/local/ysp/test_ysp.ts`
- 与样片关联的 ROI 配置
- verified 人工回合标注

这些资产只是种子数据。旧 trace、参数、阈值和效果结论不进入新 baseline。ROI 是可用的 benchmark 元数据，不是所有候选算法必须依赖的输入。

实现级样片清单在 `datasets/badminton-v1/manifests/rally-benchmark.json`。
首版复用固定机位单打种子样片，记录源时间轴、CFR 时间戳生成方式、帧数、
时长、关联标注版本和 ROI。该样片已反复用于历史诊断，清单标为
`diagnostic`，不作为未接触的模型选型测试集；新来源仍按来源与
`split_group_id` 隔离。现有人审起止点不因诊断而重写。

数据集清单必须记录样片标识、来源时间轴、时长、帧率或时间戳生成方式、标注版本和可用辅助元数据。人工标注至少包含：

```text
RallyAnnotation(
  rally_id,
  start_ms,
  end_ms,
  review_status
)
```

baseline 只使用 `review_status = verified` 的区间计算正式指标。

早期试验允许把同一原录像的部分片段用于调试，其余片段在配置固定后作留出检查，
但须标为同来源诊断，不能据此宣称独立来源验收或跨机位泛化。查看留出结果后再调整
算法，本轮留出结果也转为调试证据；正式验收仍需来源及相关会话隔离。

## 辅助训练与诊断数据

球场几何和人员轨迹数据用于调研候选路线，不替代回合区间 benchmark，也
不表示人物或跟踪路线已经成为正式架构。

- 数据多样性按独立场馆机位计算，不按同一比赛的帧数计算。
- 10 个 verified 独立机位只用于验证采集、审核、拟合和标注闭环。首个
  可训练 baseline 从 30 个 verified 机位开始，其中至少 24 个非转播
  机位、12 个隔离的 `split_group_id`；此数量仍是学习曲线的起点，
  不是“样本充分”的验收结论。
- 初始 baseline 后按错误簇和学习曲线每轮增加 10 个独立机位，优先补充
  当前最弱的环境、视角和人员困难场景，不按固定总帧数盲目扩充。
- 球场人工标注只包含可明确识别的标准控制点。至少 4 个非共线控制点
  才能拟合球场平面到图像的 homography。
- 视觉模型可以生成球场控制点 proposal，但原始 proposal、模型版本、
  prompt 版本和输入帧哈希必须不可变保存。人工决定另存为 review
  sidecar；含不确定点的 proposal 不得直接提升为 draft 标注。
- 经人工逐点接受或修正的模型 proposal 可以写入 draft，但点位来源仍
  记录为 `manual`，并额外记录
  `annotation_origin=model_assisted_human_verified`，以便回查原始模型
  输出和后续人工抽检。
- 拟合可以产生画幅外六点，但必须区分 `manual` 与
  `geometry_inferred`；推断点经人工确认且显式允许后才能进入弱监督集。
- 人员标注使用通用 `person` track，以及
  `role=participant|non_participant|unknown` 和
  `court_side=near|far|outside|unknown`。人员任务必须关联 verified
  球场几何，不把场外人员静默当成检测负样本。
- 数据切分同时隔离来源和 `split_group_id`，防止同一场馆或拍摄会话
  泄漏到不同分区。
- `adjacent_court`、`extra_people` 和 `occlusion_or_exit` 三类人员选择
  困难场景各至少覆盖 5 个 verified 独立机位；专业转播不计入这些困难
  场景的覆盖量。

辅助数据的详细 schema 和操作流程由仓库级
[素材整理 Skill](../../.agents/skills/curate-badminton-training-data/SKILL.md)
维护。

## 统一评估口径

评估器必须保存算法版本、配置、数据集清单版本、逐回合匹配结果和汇总结果，使同一输入可以重复运行。

预测与标注先按正时间重叠建立关系，再通过最大化总 temporal IoU 的一对一匹配计算边界误差。评估器同时保留匹配前的重叠关系，用于识别误切和误合并。首个 baseline 至少输出：

| 指标 | 定义 |
| --- | --- |
| 起点达标 | 预测起点落在闭区间 `[truth.start_ms - 1500, truth.start_ms]` 内；提前最多1.5秒可接受，晚开始没有容忍 |
| 终点达标 | 预测终点落在闭区间 `[truth.end_ms, truth.end_ms + 1500]` 内；延后最多1.5秒可接受，早结束没有容忍 |
| 双边达标 | 一对一匹配的同一个预测同时满足起点、终点达标；分别报告起点、终点、双边达标数量及占全部verified目标回合的比例 |
| 起点超限误差 | `max(0, pred.start_ms - truth.start_ms, truth.start_ms - 1500 - pred.start_ms)`；区间内为0，区间外为距最近允许边界的距离 |
| 终点超限误差 | `max(0, truth.end_ms - pred.end_ms, pred.end_ms - truth.end_ms - 1500)`；区间内为0，区间外为距最近允许边界的距离 |
| 漏检 | 没有任何正时间重叠预测的人工回合数量 |
| 误报 | 没有任何正时间重叠目标回合的计分预测数量；已确认排除事件对应的完整预测按上述规则忽略 |
| 误切 | 对每个人工回合计算 `max(0, 正重叠预测数 - 1)` 后求和 |
| 误合并 | 对每个预测区间计算 `max(0, 正重叠人工回合数 - 1)` 后求和 |
| 输出延迟 | `emitted_at_ms - end_ms`，报告逐回合值及 mean、P50、P95、max |
| 实时处理倍率 | 输入源时长除以处理墙钟时长；`1.0` 表示实时 |

边界恰好接触但没有正时长交集不算重叠。无法一对一匹配的预测仍需保留；
未匹配预测可能是重复切分，不能直接全部称为误报。

统一评估器为 `backend/app/vision/rally_eval.py`，版本 `rally-iou-v3`。
`v2`引入已确认事件排除和误报计数；`v3`在其基础上采用上述单向1.5秒容忍规则。
最大化总 temporal IoU 使用允许不匹配的全局一对一分配，不使用贪心匹配，
也不先合并人工区间。未匹配不等于漏检：被一个长预测重叠的多个真值中，
只有一个可被匹配，但其余仍需通过原始重叠关系统计误合并。

报告以三类边界达标数量/比例为主，不再以绝对误差均值判断边界质量。
达标率的分母包含未匹配目标，未匹配回合不算达标，防止漏检或误合并抬高比例；
它是边界指标，不能代替误报、误切、误合并等整体判定。没有目标时比例为null。
起止代表值仍取人工复核start区间左端、end区间右端，不裁剪或扩张人工真值。
逐配对保存有方向的原始偏移 `pred - truth`、起终点达标标识和超限误差，
并列出未达标回合、方向和超限时长。例如起点提前2秒仅超限0.5秒，晚0.04秒则计0.04秒；
终点延后1秒达标，提前1秒则计1秒。边界允许范围包括两端，不额外加入帧级容忍。
起点、终点的误差汇总各自只包含已匹配且该边界不达标的回合，报告数量、P50、P95、max；
mean仅保留为结构化诊断，不能拿旧版绝对误差均值与新版超限误差直接比较。
允许范围不改变IoU配对、时间覆盖或非目标残留的计算，也不自动给导出视频补时。
输出延迟覆盖所有计分预测，并保存各预测的输出时刻。
空统计的 mean/P50/P95/max 为 null；P50/P95 采用排序后位置
`(n - 1) * p` 的线性插值。所有预测、verified 真值、未匹配标识、排除的
未审核标注标识及匹配前重叠关系都保存在结果中，不以单个均值隐藏漏检。

文件剪辑试验另按区间并集计算时间覆盖，重复/重叠预测只计一次：
目标时间保留比例=预测覆盖的目标时长/目标总时长；非目标时间残留比例=预测保留的
非目标时长/可计分的非目标总时长，同时报告残留秒数。两侧均移除已确认排除事件的
非目标时间，目标时间优先，不因排除窗口覆盖目标而删掉目标；跨区间预测的回合计数
仍按前述规则正常计分。没有片头片尾补时。分母为0时比例为null。
这些时间指标采用start左端/end右端的保守代表值，不等于已知精确触球/落地误差；
负例补集未单独确认时，非目标残留仅作暂定诊断。离线候选的emitted_at可记文件末尾，
不将该记账值作为实时输出延迟或与流式延迟排名。

历史诊断命令为：

```bash
.venv/bin/python backend/tests/rally_benchmark/compare_legacy.py
```

该命令只使用本地旧 trace 复核失败机制，记录配置与输入/代码 SHA-256；
结果明确标记 `legacy_diagnostic_not_new_baseline`。它不重新运行检测模型，
也不满足新候选算法必须消费视频帧的要求，不能据此接受旧算法或完成 M2。
同一评估函数可用于新候选的帧回放结果；新的实时倍率必须来自该次回放，
不得复用旧运行记录。

## 本阶段验收

在收集更多样片前，不设置数值通过阈值。本阶段要求是：

- 数据集、标注格式和评估器版本明确；
- 所有候选路线使用同一输入输出契约；
- 上述指标可重复计算并保留逐样片证据；
- 架构选型引用 benchmark 结果，而不是旧实现参数或主观观感。

## 非目标

- 生成、裁剪或保存回合视频片段；
- 识别特定击球动作或计算球速；
- 设计移动端、桌面端、摄像头或传输产品链路；
- 在 benchmark 前预先接受某个检测、跟踪、姿态或状态机方案。
