# 产品范围

## 产品目标与算法职责

首个产品是独立打包的本机网页视频剪辑应用：浏览器通过127.0.0.1访问ReactLynx页面，选择三类拍摄角度之一和MP4录像，自动生成带原声音的精简MP4，预览成片后通过系统窗口保存。首版支持单打，默认每段前后各补0.5秒，提供三档质量。具体范围见[产品任务说明](plan/video-clipping-product-task.md)，进度只维护在[路线图](plan/roadmap.md)。

回合分割器消费按源时间轴严格递增的视频帧，并在回合结束得到确认后，输出完整的开始和结束时间。分割器的对外结果是 `RallyInterval`；视频预览和编码导出由应用处理。算法可以延迟确认结束并回填开始时间。

## 必须具备的能力

### 流式输入

- 接受带 `frame_id`、`timestamp_ms` 和图像的帧。
- 时间戳必须严格单调递增。
- 处理只依赖当前帧和历史状态，不读取未来帧。
- 核心契约不绑定本地文件、摄像头或网络协议。

### 完整区间输出

- 每个已确认回合只输出一次。
- 输出至少包含 `rally_id`、`start_ms`、`end_ms` 和 `emitted_at_ms`。
- 置信度和诊断证据可以存在，但调用方不能依赖它们必填。
- 未确认的候选状态属于实现内部细节。

### 可复现评估

- 样片、标注和配置有明确版本。
- 同一评估器计算起止误差、漏检、误切、误合并、输出延迟和实时处理倍率。
- 不同候选算法使用同一输入输出契约和 benchmark。
- 收集更多样片前不设置数值通过阈值。

## 当前数据范围

第一份 benchmark 使用 `datasets/badminton-v1/local/ysp/test_ysp.ts`、关联 ROI 和 verified 人工回合标注。ROI 是可用的辅助数据，不是产品输入契约，也不是所有路线必须依赖的特征。

## 应用与分割器的边界

- 分割器不负责输出、裁剪、编码或管理视频；首个应用负责视频输入、临时任务、成片预览、质量选择与连续导出。
- 首版不接入Android采集、编辑器、历史任务或账号；标签页断线60秒后取消并清理临时内容，模型缓存持续复用。

## 非目标

- 识别特定击球动作、生成精彩时刻或计算球速；
- 新设计移动端、桌面端或摄像头产品，以及新增采集与网络协议；
- 规定分割器必须使用某种传输、存储、界面或部署方案；
- 在 benchmark 前预设人物检测、跟踪、姿态、球轨迹、音频、状态机或端到端模型为正式方案。
