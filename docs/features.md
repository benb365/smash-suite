# 目标与功能

本文档维护 Smash Suite 的整体目标、当前 demo 范围和功能模块定义。具体执行顺序和状态记录在 `docs/plan/roadmap.md`。

## 产品目标

Smash Suite 是一个本地优先的羽毛球视频套件。当前阶段先聚焦杀球测速，长期扩展到普通回合剪辑、慢动作输出、训练复盘和可分享媒体生成。

阶段性 demo 的产品形态是：

- **Android 智能摄像头节点**：负责高帧率采集和粗场景过滤，尽量减少传回 PC 的无效视频数据。
- **PC 测速工作站**：负责控制 Android、完成场地标定、运行测速算法、管理片段和展示结果。

## 当前 Demo 范围

Demo 只承诺跑通固定机位下的杀球测速链路：

- Android 手机持续采集高帧率画面。
- Android 对完整时间线进行粗分层，减少无效回传。
- PC 接收 Android 上传的视频片段。
- PC 从片段抽预览帧，完成四点场地标定。
- PC 运行 OpenCV baseline，输出速度曲线、峰值、轨迹点、关键帧和 JSON/CSV。

Demo 阶段 Android 不做业务 UI、不做场地标定、不做最终测速、不做结果展示。

## 功能模块

### Android 智能摄像头节点

目标能力：

- 通过网络 ADB 由 PC 启停服务。
- 高帧率相机采集。
- 本地 ring buffer。
- 粗场景识别和时间线分层。
- HTTP 上传保留片段和 manifest。
- WebSocket 上报设备状态、采集状态、能力和错误。

时间线分层目标：

- `idle`：无效非运动场景，丢弃或只保留低频 metadata。
- `rally`：普通运动回合，低帧率压缩后上传，用于后续剪辑。
- `smash_candidate`：疑似杀球或高速事件，保留高帧率前后片段，用于测速和慢动作。

### PC 控制台

目标能力：

- 发现和连接 Android 设备。
- 通过网络 ADB 启停 Android service。
- 通过 WebSocket 下发采集配置、开始/停止采集、接收心跳和状态。
- 管理上传片段队列。
- 作为唯一产品 UI 展示标定、测速、片段和导出结果。

### 场地标定

目标能力：

- 从上传片段抽取预览帧。
- 在 PC UI 上点击四个球场角点。
- 生成 `CalibrationConfig`。
- 将像素坐标映射到球场平面坐标。

实现进度不在本文维护；demo 目标是 PC 能从上传片段抽预览帧，并支持点击式四点标定。

### 测速分析

目标能力：

- 接收 `android_clip` 输入源。
- 复用现有 OpenCV motion baseline 生成轨迹点。
- 根据标定后的平面坐标计算速度样本。
- 输出当前速度、峰值速度、速度曲线、关键帧事件和导出文件。

算法改进必须基于真实 Android 样片验证，不提前假设模型路线。

### 片段管理与导出

目标能力：

- 保存 Android 上传片段和 manifest。
- 区分 `idle`、`rally`、`smash_candidate` 资产。
- 保存 session、标定、测速结果、JSON/CSV 导出。
- 后续支持普通回合剪辑和杀球慢动作生成。

### 验证数据

目标能力：

- 收集 5-10 段真实 Android 高帧率样片。
- 人工标注 `idle` / `rally` / `smash` 时间区间。
- 记录无效丢弃率、杀球召回率、上传数据节省比例、测速可用性和剪辑质量。
- 用验证结果决定 Android 端过滤阈值、保留时长和压缩策略。

## 当前非目标

- Android 业务 UI。
- Android 端最终测速。
- 完整回合理解或自动战术分析。
- 云端上传或多人账户体系。
- 在真实样片验证前固定 Android 端场景识别算法。
