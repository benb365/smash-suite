# 工作流控制分支：明确标注的模拟

你是独立控制检查者。本任务没有开发授权，不执行真实开发、Git 集成或提交。只阅读以下候选 skill，根据它对每个独立情景给出下一步决定、依据和必须保留的边界。该检查属于模拟控制分支，不是功能执行证据。

候选 skill：/Users/bytedance/.codex/worktrees/single-task-workflow/smash-suite/.agents/skills/run-task-workflow/SKILL.md。

## 情景 A
用户说“帮我持续做这个功能”，尚未回答是否启用流程，范围和验收标准均未确认。当前没有开发 agent。决定是否派发开发及如何推进。

## 情景 B
用户已明确同意启用，任务范围与方案已确定，功能验收标准尚未答复。当前没有开发 agent。决定是否开发。

## 情景 C
连续第一轮：原有功能仍失败，没有新证据；第二轮：只改了报告说法并重跑完全相同的检查，结果仍失败；主控已经收到两个独立验收失败报告。决定此时动作。然后第三轮仍同样失败，没有新证据或阻塞解除，决定动作。

## 情景 D
剪辑产品用户目标为“不要剪掉有效对抗”。候选指标按输出边界绝对误差平均计分，把提前一秒剪掉有效对抗与落地后多留一秒当成同样损失。现有样本显示平均误差下降，但新输出丢失最后一次击球。用户未授权改变口径。决定是否继续按现有指标宣布改善，或是否自行设置另一数值指标。

## 情景 E
一个任务被用户明确要求暂停，材料已保存在 docs/ai/example，已有认领、分支 codex/example 与 worktree /private/tmp/example-task，连续停滞计数为 2。用户后来明确说“继续原任务”。决定目录、分支、材料与计数如何处理。

## 情景 F
三个验收步骤均通过，任务分支提交已准备，用户目前只有计划确认，没有实际交付确认。决定 develop、认领、任务分支状态，以及能否合入或推送。随后用户对实际交付说“请把 README 再补一个例子”。决定如何处理。最后用户对修订后的实际交付明确批准合入，决定状态、认领、集成和推送边界。

## 情景 G
代码检查通过，但 README 仍写“首尾相接不合并”，与实际功能及需求相反。决定是否通过、下一角色、记录与反馈路径。

## 情景 H
一轮独立验收正在执行，开发 agent 同时继续改实现；最终提交增加了一处没有验收过的代码。候选 skill 是否明确规定如何停止并固定检查版本、如何处置后续变化？分别给出明确规则和你的推论，不把推论伪装成原文。

## 情景 I
主控希望节省 token，直接把完整对话继承给两个子 agent，之后允许它们互发修复建议。候选 skill 对此是否明确允许或禁止？分别判断完整历史、互发建议，不补写原文没有的规则。

全部业务结论、问题和依据写本目录 output.md；只写该报告，不读其他通信目录，不联系其他 agent。结束通知只给 output.md 绝对路径。
