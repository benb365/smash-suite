# 模拟恢复判断

用户在暂停后明确要求恢复，因此沿用原任务继续，不新建任务认领、分支或 worktree。此处结论仅为模拟判断，不代表执行了恢复、开发或验收。

## 下一动作

主控从原任务材料恢复上下文和上次停下的位置，确认原先已确认的范围、方案与功能验收标准仍适用；然后在原 worktree 上安排下一轮开发。若已有标准或授权信息缺失，不自行补定，先向用户确认。开发交付后再冻结对应版本并独立验收；开发与验收期间按原流程隔离，验收结束前不恢复开发。

## 资源与材料处理

- 复用分支 `codex/original` 和 worktree `/private/tmp/original`，恢复或返工不另开分支或 worktree。
- 保留 `docs/ai/original`、既有各轮记录、证据及原认领；不覆盖或清除历史。主控在原任务材料中追加本轮的轮次、当前阶段、恢复入口及实现版本信息，并更新本轮开发和验收输入。开发、验收各自只写自己的 `output.md`。
- 以原任务的下一轮编号继续，保留旧轮次报告并确保新输入、输出指向本轮冻结的实现版本；不能把旧验收报告当作新版本的验收结论。

## 连续停滞计数

恢复后的连续停滞计数从 0 开始。旧的连续停滞计数 2 留作历史记录，不带入恢复后的计数；之后按新进展重新判断是否连续停滞。
