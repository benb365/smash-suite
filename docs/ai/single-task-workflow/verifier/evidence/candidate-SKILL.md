# 单任务持续开发与验收

把一个已确认的任务推进到独立验收，并把可审阅的结果交给用户。只处理该任务；结束后等待用户决定下一项。

## 启动

适用时先询问用户是否启用本流程，并确认任务范围、方案和功能验收标准。用户已经明确授权这些内容时直接继续，不重复询问。没有确认前不派发开发，也不自行缩小或替换标准。

从使用目的和错误代价判断方案是否有效。指标若与用户价值不符，用具体案例说明风险和建议，请用户确认后再调整；不得自行设定或改变验收口径。未确认的决策、缺少的权限、数据或环境条件及时交回主控询问。

## 角色与材料

- 主控维护 `docs/ai/<任务名>/task.md`、开发与验收各自的 `input.md`，中转用户决策和两方结果，并维护路线图进度。
- 开发在独立任务 worktree 实施，只读已批准材料及自己的通信目录；只写自己的 `output.md`、任务实现和其所属文档。
- 验收与开发隔离，只读任务材料和自己的通信目录；只写自己的 `output.md`。验收可运行检查并产生临时结果，但不修改实现或验收标准。
- 开发和验收不直接交流，也不读取对方通信目录。主控是唯一中转；给子 agent 的工具指令只包含文件路径和生命周期指令，业务要求写入文档。
- 修改前检查当前分支与工作区状态，保留已有改动。只阅读任务所需的代码、需求、文档和证据。

## 一轮开发和独立验收

一轮是一份开发交付及其对应的独立验收。验收固定本轮版本，依次完成：

1. 按已确认标准检查功能，并独立重跑关键验证；必要条件未执行就不能通过。耗时实验检查完整证据，有疑点时重跑。
2. 审查本轮代码差异，检查正确性、范围和必要性。
3. 检查本轮文档准确、易读、简洁，相关入口和链接有效。

功能、代码或文档任一项失败，均退回主控说明证据、缺口和建议。主控据此决定返工或向用户询问，不以重复检查或改写结论算进展。连续两轮没有确认目标的改善、检查通过、阻塞解除或推动后续的新证据时，调整排查方向；连续三轮没有实质进展时停止相关运行，保存材料并等待用户。权限、数据、环境或范围决策缺失时及时停止依赖它的步骤。

中断后经用户明确恢复，继续使用原认领、分支、worktree 和记录，并重新计算连续停滞轮数。

## 交付、状态与集成

每轮报告实际修改、执行的验证、证据入口、未验证假设和阻塞；明确区分检查通过、仅确认启动和未执行。正式证据归所属模块、应用或数据集，逐次执行记录放在 `docs/ai/`。

独立验收通过后，在任务分支本地提交已验收实现并保留 worktree，不推送或合入。任务分支状态记为“已完成，待人工确认”；develop 仍记“进行中”并保留认领。人工要求修改时，在原分支返工并复验。只有用户确认实际交付后，主控才一次集成到 develop、移除已结束认领、更新状态并验证受影响范围。计划确认不代表集成许可。之后等待用户决定下一项任务。
