# 文件输入模块与实时模拟实测

2026-10-05。运行环境：Apple M3 Pro、36 GiB 内存，现有 Python 3.9.6 / PyTorch 2.8.0 / MPS，新增 PyAV 14.2.0。模型和视频均为本地已有文件。

## 实现与边界

`FileFrameSource` 以 PyAV 解码原始 BGR 图像，用首帧 PTS 为零点保留源时间间隔。支持 offline 尽快处理和 realtime 按原速模拟。一个输入线程、一个推理消费者，最多六帧排队；实时最旧待处理或正在处理帧超过计划时刻五秒时终止，离线只使用有界阻塞。

帧接口仍为 `TimestampedFrame`，输出仍为 `RallyInterval`。模型仅加载一次并预热；保留三帧输入、512×288 缩放、选点及回合参数。TrackNet 只增加计时，移除这些计时语句后源码 SHA256 与修改前完全相同，见 `algorithm-preservation.json`。源图不降帧、不自动降画质，不透视拉正，不实时编码预览。性能、追球和判定日志按批写入；回合区间在确认后立即刷新 rally-intervals.jsonl，并向标准输出写 JSON 事件。异常写入 result.json，并返回非零退出码。

最终版本另以原样片 70 秒窗口实跑，确认第一回合在既有标注结束后 0.558 秒完成文件刷新及事件输出；文件与事件内容一致，见 final-publication-validation.json。

本轮只实现文件适配器；真实手机、USB 摄像头、网络流尚未接入，后续通过同一帧边界适配。文件模拟延迟不包含真实采集、编码和网络传输时间，也不包含视频出片。

## 十秒目标与算法问题

原样片每轮与既有 11 个 verified 回合一一匹配，没有漏检、误切或合并。相对现有标注结束时刻，三轮共 27/33 次输出在结束后十秒内，最慢 3.556 秒；6 次提前输出，涉及第 5, 8 回合。提前输出不能作为十秒目标通过，仍是原判定算法的边界问题。全部带符号的延迟、匹配关系和漏检/合并记录保留，不只统计成功案例。长测延迟使用分割器返回区间时刻；最终入口的文件刷新及事件发布时间另由 70 秒实跑确认。

既有标签未重新人审或改时间，结论是相对这版标签。官方和个人样片没有完整 verified 回合标签，只报告候选数与运行性能；原短回合漏检、还球误报、邻场误追仍存在；本次个人片到 EOF 仍有 active 状态，未强行补出末段回合。输入模块不构成算法准确率改进或跨机位可用性证明。

## 1080p／720p 对照

同一官方与个人源完整生成 720p 输入，H.264 / CRF18 / fast / 两个编码线程，不设置新帧率。先前 FFmpeg CLI 转码各少了最后一帧，校验失败后未运行推理；记录保留在 failed-ffmpeg-720-input-validation.json 和 transcode-diagnostics.json，不推断具体是哪一环节丢尾帧。最终以现有 PyAV 逐帧缩放，显式保存原时间基和归零后的源 PTS，完整刷新编码器尾包。整片解码检查帧数、PTS 和源 SHA256，结果见 720-input-validation.json。这是实际输入配置对照，含重编码变化，不能把所有差异仅归因于分辨率。

| 样片 | 离线播放速度倍率：原始 → 720p | 墙钟耗时减少 | 候选数：原始 → 720p |
| --- | --- | ---: | ---: |
| official-india | 2.02× → 2.21× | 8.5% | 8 → 8 |
| personal-multicourt | 1.68× → 1.85× | 8.9% | 2 → 3 |

| 样片 | 解码秒：原始 → 720p | BGR 转换秒 | 模型预处理秒 | 推理及回传秒 |
| --- | ---: | ---: | ---: | ---: |
| official-india | 13.7 → 4.2 | 7.9 → 3.7 | 13.5 → 6.9 | 74.8 → 73.9 |
| personal-multicourt | 14.4 → 5.1 | 11.5 → 5.0 | 16.3 → 8.2 | 89.8 → 88.4 |

两类样片的推理及回传约占原始输入消费墙钟时间的 84%，降源分辨率不改变固定模型计算量。本次每个配置只运行一次，速度差包含运行时波动。模型网络尺寸仍为 512×288，降源分辨率主要改变解码与预处理；各阶段耗时见 resolution-comparison.csv。解码与消费并行，各阶段之和不是墙钟总时长。候选数变化不等于准确率改善，两个输入没有完整回合真值。720p 仅保留为实验配置，默认继续使用原始画质和帧率。

## 运行与复现

```sh
models/SoloShuttlePose/.venv/bin/python backend/tests/rally_benchmark/run_live_tracknet.py \
  --video datasets/badminton-v1/local/ysp/test_ysp.ts --mode realtime --device mps \
  --output models/SoloShuttlePose/.runtime/realtime-seed
```

改 `--mode offline` 可尽快处理。`--video` 可重复传入，`--repeat` 按独立分析段循环，`--limit-s` 限定每个输入窗口，`--max-lag-s` 默认为五秒。显式 `--config` 是 FlightConfig JSON，`--annotations` 是与该源对应的人审标签；二者只允许单一视频。原样片自动复用已有 ROI/标签，其他输入默认全画面，不套用原样片坐标。

目录 `/Users/bytedance/workspace/test/meterials/outputs/realtime-input-20261005` 保存运行结果、持续运行启动时及最终代码哈希、来源 SHA256、比较配置与媒体校验。`run-post-long-run-batch.sh` 记录初始离线与转码流程，尾帧校验失败在推理前阻止该实验；修复的逐帧编码与 720p 对照另见 repair-720-pyav.sh 和 encode-720-pyav.py；`summarize.py` 生成本报告和汇总。持续运行启动后仅完善诊断字段、过载批次日志、区间即时写出、限定短窗口的标签覆盖和离线延迟空值；未改变调度、解码、推理或区间判定行为，完整离线对照使用最终版本。实时运行没有输出预览视频，现有预览工具仍可离线使用。

验证：61 项后端测试覆盖真实 VFR 容器、原速调度、时间戳异常、解码失败、有限队列、过载停止、错误诊断持久化、尾帧和 EOF 不强制输出，以及回合结果在输入 EOF 前即时可读；另以真实种子文件和人为等待 5.3 秒的推理桩验证默认五秒阈值；队列达到六帧后明确 InputOverload 停止，结果与触发停止那次处理的性能/追球日志保存于 default-overload-final。仓库检查使用 pnpm run test:backend 与 git diff --check。媒体原始文件与人审标注未改。
