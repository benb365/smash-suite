# A、C、D算法改进的确认记录

日期：2026-10-19。本文记录本次已经作出的算法取舍；后续优先级和进度仍以[路线图](../../../../docs/plan/roadmap.md)为准。

## 这次确定保留哪个版本

| 视角 | 本次决定 | 主要依据 |
| --- | --- | --- |
| A：官方比赛高视角 | 保留原方案；新短片段过滤仅作为待确认候选 | 新候选能补回A2三个回合，但会重新留下A1中3.92秒还球，尚未确认接受这个取舍 |
| C：场边低视角 | **保留已接受的改进版：原短回合过滤＋拆开间歇＋尾部候选连接** | C1输出与原方案相同；C2三个回合能够拆开，第4回合结尾已补回 |
| D：个人斜侧方 | **保留已接受的改进版：人物动作主导，结合球点、对手活动和脚点移动** | 七处目标得到改善；用户已接受四处D1剪辑退步 |

这里的“接受”是用户对本批视频中剪辑结果和已列出代价的接受。人工标注、排除事件及起止评分规则均不改，也不表示已经通过新来源的独立验收。

## C组确认了哪些取舍

- 撤回上一轮放宽短片段过滤的改动，候选最小跨度、观测数和最终短片段删除都恢复原规则。
- C1-02的31.386–34.221、38.023–38.824、73.378–74.512秒，以及C1-04的51.464–52.332秒，用户均确认不应保留。新版本已全部删除，C1四段的15个输出与原方案逐条相同。允许原方案漏掉正常短回合的取舍，不把这些正常回合改成“人工排除”。
- C2第3至5回合不再共用24.133–88.033秒的一大段，中间两段休息继续删去。
- C2第4回合结束由67.367秒延续到68.933秒，覆盖人工终点68.600秒，晚0.333秒。通过连接已有候选点补回，没有固定增加片尾秒数。用户查看后回复“很好，继续”，该轮修复结果已接受。

| C组结果 | 原方案 | 已接受改进版 |
| --- | ---: | ---: |
| C1对打时间保留 / 标注外保留 | 91.95% / 8.27秒 | 相同，且输出逐条一致 |
| C2对打时间保留 | 81.16% | 81.01% |
| C2标注外保留 | 29.17秒 | 17.60秒 |
| C2回合错误合并 / 整段漏掉 | 2 / 4个 | 0 / 4个 |
| C2起止同时合格 | 1/10 | 1/10 |

剩余问题：第4回合开头仍少0.133秒，导致总对打保留略降；恢复原短过滤后，C2第1、7、9、10回合仍漏掉。片尾可见11.60秒对打仍只保留8.20秒。部分回合边界仍多留或少留，未宣称已解决。

具体算法、六种尾部条件及来源核验见[C组报告](c-pause-boundaries-20261019.md)。已否决的放宽短过滤版本和直接使用D的两种对照保留在[上一轮报告](c2-recovery-and-d-transfer-20261019.md)，不作为此次接受的版本。

## D组确认了哪些取舍

保留已经确认的“人物动作建立回合、较弱持续活动延续回合”的改进。球点只提供支持；遮挡后人物坐标跳变不能直接建立新回合，短动作组还要检查对手活动和实际移动。

用户默认接受七处明确改善：补回D2两个漏回合、补齐第12回合结尾、连起第13回合、减少两处尾部残留、删除D1第4段还球。随后逐处接受四处D1新剪辑：第3段第4回合，第4段第3/6回合结尾，以及第2段第6回合开头。评分不因用户接受而变为合格。

| D组结果 | 原方案 | 已接受改进版 |
| --- | ---: | ---: |
| D1对打时间保留 / 整段漏掉 | 95.69% / 1个 | 96.34% / 1个 |
| D1起止同时合格 | 8/32 | 6/32 |
| D1标注外保留，含排除事件 | 111.70秒 | 105.57秒 |
| D2对打时间保留 / 整段漏掉 | 87.12% / 2个 | 98.86% / 0个 |
| D2起止同时合格 | 4/14 | 11/14 |
| D2标注外保留，含排除事件 | 35.43秒 | 23.57秒 |

剩余问题：D1仍漏一个3秒回合，仍有非回合残留及严格评分下的边界退步；D2第5回合开头少0.833秒、第8回合结尾少0.467秒。D自动选人仍可能受邻场或路人干扰，后续考虑引入C的主场筛选和球员跟踪，但这项修改尚未实施，也不计入本次成果。

具体判断方式、完整人审位置和失败尝试见[D组报告](d-person-context-20261018.md)。直接把D用于C的两种对照整体更差，没有采用为C方案。

供后续会话复查，以下标识只用于在保存的数据中精确定位，不是另一个算法名称。

| C已接受改进版 | [C组修复脚本](../../../../backup/module-reorganization-20261019/backend/tests/rally_benchmark/refine_c_pause_boundaries.py) | [C结果JSON](c-pause-boundaries-20261019.json)：`selected_variant = tail_gap800_growth300`，C1共15段、C2共8段输出 |

上述脚本依赖本机已有观测及模型运行目录中的历史辅助代码，缓存重放不代表从原视频完成了全部模型推理。JSON保存输入、源码校验值及逐片预测，人工标注保持原版本；C2片尾未完回合单列，不当作完整回合计分。

表中是原始输出段数，不是成功回合数；输出还可能包含非回合或未完回合内容，不能用段数相等代替准确性评分。

## 与产品和性能记录的关系

截至本次记录，产品的三类冻结算法尚未同步上述新C/D改进。实际产品入口为[recognize.py](../../../../backup/module-reorganization-20261019/backend/app/recognize.py)，来源见[算法来源清单](../../../../backup/module-reorganization-20261019/backend/app/algorithms/provenance.json)：C仍调用原`court_pipeline`，D仍调用较早的`refined_person`。产品中的C2是6段、D2是13段；实验接受版分别为8段、14段。要接入产品，需要另做迁移、逐条结果及完整流程核验，不能只改文档便称产品已更新。

A组新候选仍需确认“补回对打但增加还球”的取舍。性能测量按用户本次要求暂不启动：D组已有479.703秒分阶段合计及产品688.09秒识别记录都对应旧方案，不能作为最新14段方案的完整耗时。C/D的已接受版本也未因此获得新的内存峰值或最低硬件结论。
